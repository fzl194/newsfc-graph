# 图谱平台接口文档（MCP 版）

> 图谱资产管理平台对 Agent 的访问接口：**MCP 服务**（`/mcp`，5 个工具，图谱查询唯一通道）+ 一个**打点统计接口**（REST，查取用频次）。打点自动记录，无需手动调（详见 §3）。
>
> 2026-08-24（MCP 服务化）：原 SKILL 两接口 `POST /api/v1/domains`、`POST /api/v1/md` **已删除**，能力由 MCP 工具 `get_domains` / `get_md` 继承并增强（新增正文搜索 `search_md` 等）。


## 兼容接口（REST，2026-09-03 恢复，与 MCP 并行）

为兼容存量 Agent/SKILL 配置，按**原契约**恢复两个 REST 接口（2026-08-24 MCP
服务化时曾删除）；权限与 MCP 一致（skill：`can_skill` 或 `can_frontend`，
admin 全权），鉴权同样走 `X-API-Key` 请求头。打点与 MCP 行在运维页
「知识取用频次」合并计数。**新接入仍推荐 MCP**（另有 search_objects /
search_md / get_object 三工具）。

| 接口 | 请求 | 响应 |
|---|---|---|
| `POST /api/v1/domains` | 无 body | `[{id, name, md}, ...]` 全部业务域（最新版本）完整 md |
| `POST /api/v1/md` | `{"ids": ["ID", ...], "version": "可选"}` | `{id: {version, md} 或 {error, available_versions}}`；不传 version→各 id 最新现存版本；版本缺失仅该 id 计错 |

---

## 概述

| 能力 | 通道 | 用途 |
|---|---|---|
| 全部业务域 md | MCP 工具 `get_domains` | 入口定位（一次性全部域） |
| 批量取对象 md | MCP 工具 `get_md` | 全程主力（沿 `[[ID]]` 引用逐层下钻） |
| 对象元数据搜索 | MCP 工具 `search_objects` | 按 id/名称/层/网元定位对象 |
| **正文全文搜索** | MCP 工具 `search_md` | 按业务关键词召回相关 md（新能力） |
| 单对象结构化+出边 | MCP 工具 `get_object` | 看对象详情与关联关系 |
| 打点统计 | REST `GET /api/v1/telemetry/stats` | 取用频次聚合（只读，详见 §3） |
| 取用明细流 | REST `GET /api/v1/telemetry/skill-usage` | 增量导出逐条取用事件 |

## 1. MCP 服务接入

### 1.1 端点与鉴权

- **URL**：`http://<平台地址>:<端口>/mcp`（Streamable HTTP，stateless + JSON 响应）
- **鉴权**：唯一凭证 `X-API-Key` header（管理员自定义或系统生成，≥8 位无空格，无前缀要求），要求 `skill` 权限（can_skill / can_frontend / admin 任一）。无 KEY/错 KEY → HTTP 401；无权限 → 403。
- **完整接入配置**（KEY 获取、Claude Code / Cursor / 云 Agent 配置、系统提示词模板、验证排障）：见 [docs/MCP配置指南.md](docs/MCP配置指南.md)。

### 1.2 客户端配置（以 Claude Code `.mcp.json` 为例）

```json
{
  "mcpServers": {
    "graph": {
      "type": "http",
      "url": "http://127.0.0.1:8000/mcp",
      "headers": { "X-API-Key": "sk-xxxxxxxxxx" }
    }
  }
}
```

> 云 Agent 平台在平台级配置一次 KEY 即可（所有用户共用连接）；用户身份不走 header（见 §1.3）。

### 1.3 上下文参数（用户身份，每次工具调用必传）

云 Agent 场景下不同用户的工号/会话ID不同，无法静态配 header——**随每次工具调用传参**，Agent 从沙箱环境变量读取：

| 工具参数 | 沙箱环境变量 | 用途 |
|---|---|---|
| `AGENT_USERNAME` | `_AGENT_USERNAME` | 用户工号 → 打点 `operator`（追溯"谁在用"） |
| `AGENT_SESSION_ID` | `_AGENT_SESSION_ID` | 会话ID → 打点 `session_id`（会话维度统计） |

> 两个参数在全部 5 个工具上都是必填；仅用于打点归因，**不影响调用结果**。

### 1.4 管理员工具配置（2026-08-25）

admin 可在前端「MCP 工具」页（或 `GET/PATCH /api/v1/mcp-tools`）配置每个工具的
**启用开关**与**描述**，以及服务**总体说明**（instructions）。禁用 = tools/list 隐藏 +
直连调用中文报错；配置全局生效、保存即生效、重启自动恢复。详见
[docs/MCP配置指南.md](docs/MCP配置指南.md) §7。

## 2. MCP 工具明细

### 2.1 `get_domains` — 全部业务域

- **参数**：仅 §1.3 上下文参数
- **返回**：`{"domains": [{id, name, md}, ...]}`——每个域完整 md（frontmatter + 正文 + `## 边`）；多版本取最新。

### 2.2 `get_md` — 批量取对象 md（主力）

- **参数**：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `ids` | string[] | 是 | 1~**100** 个对象逻辑 ID（可含 `@` 与空格；重复自动去重保序） |
| `version` | string | 否 | 全局版本；不传 → 每个 id 各取**最新现存版本**；某 id 不在该版本 → 该 id 计错回带 `available_versions`，**不影响其余 id** |

- **返回**：`{id: {version, md} | {error, available_versions}}`——每个 id 恰好一个条目。
- **护栏**：ids ≤100 且响应总量 ≤2MB，超限整单报错（MCP isError）指引分批——防止单次结果撑爆 Agent 上下文。

### 2.3 `search_objects` — 元数据搜索

- **参数**：`q`（id/name/name_zh 子串，不搜正文）、`layer`（命令层/特性层/任务层/业务层）、`type`（优先于 layer）、`nf`、`version`、`domain`、`scenario`、`page`(1)、`size`(50)
- **返回**：`{total, rows: [{id, type, layer, nf, domain, scenario, name, versions[]}]}`（多版本合并一行）

### 2.4 `search_md` — 正文全文搜索（新能力）

- **参数**：`q`（必填，≥3 字符走相关度排序 bm25，更短按字面匹配）、`layer`/`type`/`nf`/`version`（不传 version 只搜每对象**最新版**）、`limit`(20)、`offset`(0)
- **返回**：`{total, hits: [{id, type, name, version, score, snippet}]}`——**片段摘要非全文**（`【】`高亮命中词），选中后用 `get_md` 取完整 md。
- 用途：①意图式召回（不确定 ID 时按业务关键词找 md）；②查某参数/命令名出现在哪些对象。

### 2.5 `get_object` — 单对象结构化 + 出边

- **参数**：`id`（必填）、`version`（不传 = 最新现存；版本缺失报错回带 `available_versions`）
- **返回**：`{id, type, layer, scope, nf, version, domain, scenario, frontmatter, body_md, source_path, versions[], out_edges[]}`
- ⚠ `out_edges` 仅含 curated 边（`## 边` 段显式声明）；完备遍历必须读 md 全文提取 `[[ID]]`。

## 3. 打点与统计

### 3.1 打点写入：自动，无专门接口

打点直接嵌在 MCP 工具与 REST 接口里，调用方无法也无需手动打点。`record()` 吞异常（失败仅 log），绝不阻断业务。

**三级记录**（telemetry 表）：

| level | 记录时机 | 说明 |
|---|---|---|
| `request` | 每个到达 `/mcp` 的 HTTP 请求（鉴权通过即记） | 请求轨迹 |
| `tool` | 每次 MCP 工具调用 | `endpoint=mcp:{工具名}`——搜索类工具的使用量可观测 |
| `object` | `get_md` 每个成功 id、`get_domains` 每个域 | **取用统计口径**（Agent 真正取图谱资产的次数） |

字段：`{ts, level, caller, endpoint, obj_id, obj_type, user, operator, session_id}`

- `caller`：`mcp`（MCP 通道，与用户属性解耦）/ `web` / `skill`（历史行）
- `user`：KEY 属主账号名；`operator`/`session_id`：来自工具参数 `AGENT_USERNAME`/`AGENT_SESSION_ID`

### 3.2 GET /api/v1/telemetry/stats — 打点统计（只读）

**口径**：`level=object` 且 `caller∈{skill, mcp}` 且 `endpoint∈{mcp:get_md, mcp:get_domains, /md, /domains}`（新旧口径并存，历史行无缝计入）。

- **入参**：`GET /api/v1/telemetry/stats?days=30`（1~365 天），Header `X-API-Key`
- **出参**：`{total, by_type, top_ids, timeline, by_user, by_operator, by_session}`

```json
{
  "total": 1234,
  "by_type": {"AtomTask": 560, "MMLCommand": 410},
  "top_ids": [{"id": "UDG@AtomTask@ADD URR", "type": "AtomTask", "count": 28}],
  "timeline": [{"date": "08-24 14:00", "count": 42}],
  "by_user": {"agent01": 800},
  "by_operator": {"10086": 800},
  "by_session": 37
}
```

| 字段 | 说明 |
|---|---|
| `by_operator` | 按工号计数（工具参数 `AGENT_USERNAME`） |
| `by_session` | distinct 会话数（工具参数 `AGENT_SESSION_ID`） |

### 3.3 GET /api/v1/telemetry/skill-usage — 取用明细导出（只读）

口径同 §3.2，返回逐条事件。**增量游标语义**：`since` 留空 = 全量起点；透传返回的 `next_since`（不透明游标，内部 `ts|rowid`）循环拉取直到 `has_more=false`；幂等可重放。

```json
{
  "events": [
    {"ts": "2026-08-24T02:14:05.1+00:00", "endpoint": "mcp:get_md",
     "obj_id": "UDG@AtomTask@ADD URR", "obj_type": "AtomTask",
     "user": "agent01", "operator": "10086", "session_id": "sess-77"}
  ],
  "next_since": "2026-08-24T02:14:05.1+00:00|48213",
  "has_more": false
}
```

```bash
curl -s "http://127.0.0.1:8000/api/v1/telemetry/skill-usage?limit=1000" \
  -H "X-API-Key: sk-xxxxxxxxxx"
# 增量：把 next_since 原样回传（+ 编码为 %2B）
curl -s "http://127.0.0.1:8000/api/v1/telemetry/skill-usage?since=2026-08-24T02:14:05.1%2B00:00|48213" \
  -H "X-API-Key: sk-xxxxxxxxxx"
```

## 附录

### A. 对象 ID 格式

| 类别 | 段数 | 格式 | 示例 | version |
|---|---|---|---|---|
| 跨 NF 类（业务层） | 2 段 | `{Type}@{slug}` | `BusinessDomain@business-awareness`、`NetworkScenario@charging` | 恒 `null` |
| NF 类（任务/特性/命令层） | 3 段 | `{nf}@{Type}@{name}` | `UDG@AtomTask@ADD URR`、`UDG@MMLCommand@ADD APN` | 非空（如 `20.15.2`） |

> `name` 可含空格（如 `ADD URR`），ID 原样保留，整体作为一个字符串传入。

### B. 典型下钻链（沿 `[[ID]]` 引用逐层取）

```
get_domains                → 全部业务域 md          → 锁定业务域
get_md {场景 id}            → 场景 md（决策点路由表） → 锁定场景
get_md {方案 id}            → 方案 md                → 锁定方案
get_md {task ids}          → FeatureTask/CompoundTask/AtomTask
get_md {特性/命令 ids}      → Feature / MMLCommand（按需）
```

每读一个 md，用正则 `\[\[([^\]]+)\]\]` 提取正文 + `## 边` 段里的全部 `[[ID]]` 引用，判断相关性后，把相关的 ID 收集进下一批，再次 `get_md`，循环至所需知识齐备。不确定 ID 时先用 `search_md` 按关键词召回。

### C. 错误处理

- HTTP 401：`X-API-Key` 缺失/无效 → 检查 KEY。
- HTTP 403：KEY 无 `skill` 权限 → 联系平台管理员开通。
- MCP 工具错误（isError=true）：参数校验失败 / 护栏超限（分批重试）/ 对象不存在——错误信息为中文描述，按提示修正后重试。
- `get_md` 业务级错误（对象/版本不存在）：不整体失败，看该 id 条目的 `error` 字段；按 `available_versions` 改版本重试，或跳过该 id。

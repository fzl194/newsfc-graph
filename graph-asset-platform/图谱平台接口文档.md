# 图谱平台接口文档

> 图谱资产管理平台对外提供的读接口：两个**资产接口**（访问图谱对象 md）+ 一个**打点统计接口**（查 SKILL 取用频次）。打点自动记录，无需手动调（详见 §3）。

## 概述

| 接口 | 方法 | 路径 | 用途 |
|---|---|---|---|
| 取全部业务域 | POST | `/api/v1/domains` | 一次性返回全部业务域 md（入口定位） |
| 批量取对象 md | POST | `/api/v1/md` | 按 ID 批量取任意对象的完整 md（全程主力） |
| 打点统计 | GET | `/api/v1/telemetry/stats` | SKILL 取用频次聚合（只读统计，详见 §3） |

**Base URL**：`http://127.0.0.1:8000/api/v1`（按实际部署改，下文示例均用此）

**鉴权**：两个接口都需要在请求头携带 API Key。
| Header | 必填 | 说明 |
|---|---|---|
| `X-API-Key` | 是 | 平台分配的 API Key（`sk-` 开头），用于鉴权 |
| `X-User-Id` | 建议 | 调用方用户名，用于打点/审计追溯 |
| `Content-Type` | `/md` 必填 | `application/json`；`/domains` 无 body 可不传 |

> 权限：两个接口均要求 `skill` 权限。Key 无该权限会返回 403。

## 1. POST /api/v1/domains — 取全部业务域

### 用途
业务域是业务归属的最顶层定位层（数量少、跨网元、版本恒为 null）。一次调用拿到**全部业务域的完整 md**，用于按需求关键词匹配锁定业务域。

### 入参
- **方法**：`POST`
- **路径**：`/api/v1/domains`
- **Header**：`X-API-Key`（必）、`X-User-Id`（建议）
- **Body**：无

### 出参
`200`，JSON **数组**，每个元素一个业务域：

```json
[
  {
    "id": "BusinessDomain@business-awareness",
    "name": "业务感知",
    "md": "---\nid: BusinessDomain@business-awareness\n---\n# 业务感知\n...(完整 md，含正文 + ## 边)"
  },
  {
    "id": "BusinessDomain@apn-domain",
    "name": "APN",
    "md": "..."
  }
]
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 业务域逻辑 ID，2 段 `{Type}@{slug}`（如 `BusinessDomain@business-awareness`） |
| `name` | string \| null | 域名（取自 md frontmatter 的 `name` 字段） |
| `md` | string | 该业务域对象的完整 markdown（frontmatter + 正文 + `## 边`，原样 verbatim） |

> 同一业务域若存在多版本，返回其**最新版本**的 md。

### 示例
```bash
curl -s -X POST http://127.0.0.1:8000/api/v1/domains \
  -H "X-API-Key: sk-xxxxxxxxxx" \
  -H "X-User-Id: agent01"
```

## 2. POST /api/v1/md — 批量取对象 md

### 用途
按一组对象 ID 批量取它们的完整 markdown。是访问图谱的**全程主力接口**——沿对象 md 里的 `[[ID]]` 引用，逐层批量取下一批对象。单个对象也走本接口（`ids` 传一个）。

### 入参
- **方法**：`POST`
- **路径**：`/api/v1/md`
- **Header**：`X-API-Key`（必）、`X-User-Id`（建议）、`Content-Type: application/json`（必）
- **Body**（JSON）：

```json
{
  "ids": ["NetworkScenario@charging", "ConfigurationSolution@charging-online", "UDG@AtomTask@ADD URR"],
  "version": "20.15.2"
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `ids` | string[] | 是 | 1~N 个对象逻辑 ID（版本无关）。ID 可含 `@` 与空格。**同 id 重复自动去重保序**（只算一次）。 |
| `version` | string | 否 | 全局版本。不传 → 每个 id 各自取**最新现存版本**。某 id 不在该版本 → 该 id 计错（回带可用版本），**不影响其余 id**。 |

### 出参
`200`，JSON **对象**，key = 请求的 id，value = 该 id 的结果。**每个 id 恰好一个条目**，便于遍历。

```json
{
  "NetworkScenario@charging": {
    "version": null,
    "md": "---\n...(完整 md)..."
  },
  "ConfigurationSolution@charging-online": {
    "version": null,
    "md": "..."
  },
  "UDG@AtomTask@ADD URR": {
    "version": "20.15.2",
    "md": "..."
  },
  "NotExisted@xxx": {
    "error": "对象不存在",
    "available_versions": []
  },
  "UDG@AtomTask@SOME CMD": {
    "error": "版本不存在: UDG@AtomTask@SOME CMD@20.14.0",
    "available_versions": ["20.15.2"]
  }
}
```

每个 id 的 value 有两种形态：

**① 成功** → `{version, md}`

| 字段 | 类型 | 说明 |
|---|---|---|
| `version` | string \| null | 解析到的版本。NF 类对象（如 `UDG@AtomTask@*`）为具体版本号（`"20.15.2"`）；跨 NF 类对象（业务域/场景/方案）恒为 `null`。 |
| `md` | string | 该对象的完整 markdown（frontmatter + 正文 + `## 边`，原样 verbatim）。 |

**② 失败** → `{error, available_versions}`（该 id 出错不影响其他 id 的正常返回）

| 字段 | 类型 | 说明 |
|---|---|---|
| `error` | string | 错误描述。`"对象不存在"`（id 完全找不到）或 `"版本不存在: {id}@{version}"`（id 存在但指定版本缺失）。 |
| `available_versions` | string[] | 该 id 实际拥有的版本列表，供调用方改版本重试。对象不存在时为 `[]`。 |

### 版本解析规则（重要）
- **不传 `version`**：每个 id 落到**该 id 自己的最新现存版本**（不是"网元最新版本"）。即某 id 若没跟上最新版本，会落到它自己的最新版本，**不报错**。
- **传 `version`**：所有 id 统一用该版本；某 id 在该版本不存在 → 该 id 计错并回带 `available_versions`，其余 id 照常返回。

### 示例

```bash
# Git Bash / Linux / macOS
curl -s -X POST http://127.0.0.1:8000/api/v1/md \
  -H "X-API-Key: sk-xxxxxxxxxx" \
  -H "X-User-Id: agent01" \
  -H "Content-Type: application/json" \
  -d '{"ids":["NetworkScenario@charging","ConfigurationSolution@charging-online"]}'

# Windows cmd.exe（echo 管道，避免 cmd 引号转义问题）
echo {"ids":["NetworkScenario@charging"]} | curl -s -X POST http://127.0.0.1:8000/api/v1/md \
  -H "X-API-Key: %GRAPH_API_KEY%" \
  -H "Content-Type: application/json" \
  --data-binary @-

# 单个对象也走批量接口
curl -s -X POST http://127.0.0.1:8000/api/v1/md \
  -H "X-API-Key: sk-xxxxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{"ids":["UDG@AtomTask@ADD URR"]}'
```

## 3. 打点与统计

### 3.1 打点写入：自动，无专门接口
**没有"写打点"的 HTTP 接口**。打点直接嵌在资产接口里——每次调 `POST /md`、`POST /domains`（以及其它对象/测试接口），接口内部自动调 `record(...)` 往 jsonl 日志追加一条记录。调用方无需、也不能手动打点。

- 打点是**观测用、非功能性**：`record()` 内部吞异常，打点失败只 log warning，**绝不阻断业务**（接口照常返回数据）。
- 两级记录：
  - **请求级**（`level=request`）→ `telemetry_requests.jsonl`
  - **对象级**（`level=object`，记录具体被取的 `id` / `type`）→ `telemetry_objects.jsonl`
- 每条记录字段：`{ts, user, operator, caller, endpoint, id, type, level}`
  - `caller`：调用方（`skill` / `web`），由鉴权中间件按 Key 权限派生，**不信客户端自报的 header**
  - `operator`：SKILL 调用者工号（取自 `X-User-Id`），前端调用为空
- 打点**只追加访问日志，不改图谱资产内容**。资产内容更新走 `POST /api/v1/import`（上传资产包 zip 入库），与打点无关。

### 3.2 GET /api/v1/telemetry/stats — 打点统计（只读）

查询 SKILL 取用频次聚合。**只统计 `caller=skill` 且 `endpoint∈{/md, /domains}` 的对象级记录**（即 Agent 真正取图谱资产的次数），前端浏览不计入。

#### 入参
- **方法**：`GET`
- **路径**：`/api/v1/telemetry/stats`
- **Header**：`X-API-Key`（必）、`X-User-Id`（建议）
- **Query**：

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `days` | int | 否 | 30 | 统计最近 N 天，范围 1~365 |

#### 出参
`200`，JSON 对象：

```json
{
  "total": 1234,
  "by_type": {"AtomTask": 560, "MMLCommand": 410, "NetworkScenario": 120},
  "top_ids": [
    {"id": "UDG@AtomTask@ADD URR", "type": "AtomTask", "count": 28},
    {"id": "NetworkScenario@charging", "type": "NetworkScenario", "count": 15}
  ],
  "timeline": [
    {"date": "07-30 14:00", "count": 42},
    {"date": "07-30 15:00", "count": 35}
  ],
  "by_user": {"agent01": 800, "agent02": 434},
  "by_operator": {"10086": 800, "10087": 434}
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `total` | int | 统计期内 SKILL 取用总次数 |
| `by_type` | object | 按对象类型计数（`{type: count}`） |
| `top_ids` | array | 取用最多的前 20 个 id，每项 `{id, type, count}` |
| `timeline` | array | 按小时的取用分布，每项 `{date: "MM-DD HH:00", count}`（当天内波动可见） |
| `by_user` | object | 按平台用户计数（`{user: count}`） |
| `by_operator` | object | 按 SKILL 调用者工号计数（`{operator: count}`，取自 `X-User-Id`） |

#### 示例
```bash
# 默认 30 天
curl -s http://127.0.0.1:8000/api/v1/telemetry/stats \
  -H "X-API-Key: sk-xxxxxxxxxx"

# 最近 7 天
curl -s "http://127.0.0.1:8000/api/v1/telemetry/stats?days=7" \
  -H "X-API-Key: sk-xxxxxxxxxx"
```

### 3.3 GET /api/v1/telemetry/skill-usage — SKILL 取用明细导出（只读）

按条返回 SKILL 取用资产的**原始明细**，供外部系统增量同步。口径同 §3.2（`caller=skill` 且 `endpoint∈{/md, /domains}` 的对象级记录），但返回逐条事件而非聚合数字。

#### 入参
- **方法**：`GET`
- **路径**：`/api/v1/telemetry/skill-usage`
- **Header**：`X-API-Key`（必）、`X-User-Id`（建议）
- **Query**：

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `since` | string | 否 | 空 | 增量游标。空=全量起点；透传上批返回的 `next_since` 做增量轮询；也可传一个 ISO8601 时间作为起点过滤（含边界） |
| `limit` | int | 否 | 1000 | 单批最大行数，范围 1~10000 |

#### 出参
`200`，JSON 对象：

```json
{
  "events": [
    {"ts": "2026-08-13T02:14:05.123456+00:00", "endpoint": "/md", "obj_id": "UDG@AtomTask@ADD URR", "obj_type": "AtomTask", "user": "agent01", "operator": "10086"},
    {"ts": "2026-08-13T02:14:06.011203+00:00", "endpoint": "/domains", "obj_id": "BusinessDomain@charging", "obj_type": "BusinessDomain", "user": "agent01", "operator": "10086"}
  ],
  "next_since": "2026-08-13T02:14:06.011203+00:00|48213",
  "has_more": true
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `events` | array | 本批取用明细，每项 `{ts, endpoint, obj_id, obj_type, user, operator}` |
| `events[].ts` | string | ISO8601 UTC 时间戳 |
| `events[].endpoint` | string | `/md` 或 `/domains` |
| `events[].obj_id` | string | 被取用的对象 id |
| `events[].obj_type` | string | 对象类型（`Feature`/`AtomTask`/`BusinessDomain`…） |
| `events[].user` | string | 平台调用账号 |
| `events[].operator` | string | SKILL 调用者工号（取自 `X-User-Id`；调用方未传则为空） |
| `next_since` | string | 不透明游标，作为下次请求的 `since` 原样透传；无更多数据时停在末位 |
| `has_more` | bool | 是否还有未取完的明细 |

#### 增量轮询约定
1. 首次 `since` 留空（或传一个 ISO8601 起点）拉取；
2. 把返回的 `next_since` 原样作为下次 `since`，循环直到 `has_more=false`；
3. `next_since` 为**不透明游标**（内部含时间戳+行位，跨同时间戳行也能稳定推进），不要自行解析或拼接；
4. 接口幂等可重放：同一 `since` 始终返回同一批事件（打点表只追加、不修改）。

#### 示例
```bash
# 首次拉取（全量起点）
curl -s "http://127.0.0.1:8000/api/v1/telemetry/skill-usage?limit=1000" \
  -H "X-API-Key: sk-xxxxxxxxxx"

# 增量轮询（透传上批 next_since；注意 + 需编码为 %2B，否则会被当作空格）
curl -s "http://127.0.0.1:8000/api/v1/telemetry/skill-usage?since=2026-08-13T02:14:06.011203%2B00:00|48213&limit=1000" \
  -H "X-API-Key: sk-xxxxxxxxxx"
```

## 附录

### A. 对象 ID 格式
图谱对象 ID 是**版本无关**的逻辑 ID，分两种：

| 类别 | 段数 | 格式 | 示例 | version |
|---|---|---|---|---|
| 跨 NF 类（业务层） | 2 段 | `{Type}@{slug}` | `BusinessDomain@business-awareness`、`NetworkScenario@charging`、`ConfigurationSolution@charging-online` | 恒 `null` |
| NF 类（任务/特性/命令层） | 3 段 | `{nf}@{Type}@{name}` | `UDG@AtomTask@ADD URR`、`UDG@MMLCommand@ADD APN`、`UDG@Feature@GWFD-010101` | 非空（如 `20.15.2`） |

> `name` 可含空格（如 `ADD URR`），ID 原样保留，调用时整体作为一个字符串传入 `ids`。

### B. 典型下钻链（沿 `[[ID]]` 引用逐层取）
```
POST /domains              → 全部业务域 md          → 锁定业务域
POST /md {场景 id}          → 场景 md（决策点路由表） → 锁定场景
POST /md {方案 id}          → 方案 md                → 锁定方案
POST /md {task ids}         → FeatureTask/CompoundTask/AtomTask
POST /md {特性/命令 ids}     → Feature / MMLCommand（按需）
```
每读一个 md，用正则 `\[\[([^\]]+)\]\]` 提取正文 + `## 边` 段里的全部 `[[ID]]` 引用，判断相关性后，把相关的 ID 收集进下一批 `ids`，再次 `POST /md`，循环至所需知识齐备。

### C. 错误处理建议
- HTTP 401：`X-API-Key` 缺失或无效 → 检查 Key。
- HTTP 403：Key 无 `skill` 权限 → 联系平台管理员开通。
- 业务级错误（对象不存在 / 版本不存在）：不靠 HTTP 码，看响应体里该 id 的 `error` 字段；按 `available_versions` 改版本重试，或跳过该 id。

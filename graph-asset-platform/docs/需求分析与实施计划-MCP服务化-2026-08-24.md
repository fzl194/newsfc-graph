# 需求分析与实施计划——图谱查询 MCP 服务化（v2，含对抗审查吸收）

- 日期：2026-08-24（v2 同日修订：吸收对抗审查 13 项发现，见 §12）
- 状态：**待专家终审**（批准前不动代码）
- 关联：`定制点对抗评审与决策清单-2026-08-18.md`（平台定制点流程先例）

## 0. 背景与目标

Agent（SKILL）当前以 curl 直调两个 REST 端点（`POST /domains`、`POST /md`）访问图谱。
目标：**图谱查询全面迁移为 MCP（Model Context Protocol）服务**——

1. Agent 通过 MCP 工具调用取图谱知识（工具即上述两接口的能力继承 + 搜索增强）
2. 工具集补齐**正文全文搜索**能力，支撑"按用户意图召回相关 md"
3. MCP 工具调用必须有**打点记录**（延续现有 telemetry 语义与统计口径）
4. **旧两接口（POST /domains、POST /md）删除**——未来对 Agent 只提供 MCP，不提供单独 POST 请求
5. MCP 服务必须鉴权（复用现有用户/KEY 体系）

## 2. 总体架构

```
Agent (Claude Code / 各 MCP 客户端)
  │  MCP Streamable HTTP（JSON-RPC，POST + SSE 响应流）
  │  header：X-API-Key（鉴权，唯一凭证，客户端配置一次）
  │  tool 参数：_AGENT_USERNAME（工号）+ _AGENT_SESSION_ID（会话ID）每次调用动态传入（打点用）
  ▼
FastAPI 同进程
  └─ /mcp：MCP SDK 会话管理 ASGI 子应用
       外包一层【纯 ASGI 鉴权中间件】（≠ BaseHTTPMiddleware，见 §2.1）
  │
  ├─ MCP 工具层（薄封装，无业务状态；sync def → 线程池执行，不阻塞事件循环）
  │    get_domains / get_md / search_objects / search_md / get_object
  │    ├─ 读: Service 索引单例（内存 raw_md / nodes / edges）
  │    ├─ 搜索: md_fts（FTS5 trigram 虚拟表，随 reindex 增量维护）
  │    └─ 打点: telemetry（level=tool + level=object，见 §5）
  ▼
platform.db（objects / edges / md_fts / telemetry / users）
```

### 2.1 鉴权：纯 ASGI 中间件（吸收审查 A1/A2/A3）

- **不扩展 `AuthMiddleware`（BaseHTTPMiddleware）拦 /mcp**——该基类对 SSE 流式响应有缓冲/挂起的历史问题（POST+SSE 响应经 call_next 转发可能被缓冲，常驻 GET 流收不到 keep-alive 导致客户端误判断连重连）
- 改为：**纯 ASGI 中间件包裹 MCP 子应用**——只读 header 鉴权（X-API-Key），不缓冲 body、不包装响应流
  - 无 KEY/未知 KEY → 裸 HTTP 401（JSON，MCP 客户端可读，审查 A4：Claude Code 会提示鉴权失败，预期行为）
  - 权限要求 `skill`（can_skill / can_frontend / is_admin 任一，与旧两接口一致）
- **request 级打点在鉴权通过后立即记**（不等响应完成——流式响应可能数十分钟，事后打点 ts 失真，审查 A2）
- **会话管理交给 MCP SDK 的 session manager**（Streamable HTTP 的 DELETE 终止/GET 流/TTL 均内建）；配置会话 TTL 与空闲超时（审查 A3），测试补 DELETE 会话用例

### 2.2 用户身份传递（云 Agent 场景，2026-08-24 用户补充）

**背景**：MCP 连接由云 Agent 平台级配置（X-API-Key 静态鉴权没问题），但每个用户的工号/会话ID不同，无法静态配 header——**必须随每次 tool 调用动态传入**。

**header 与参数的职责划分（最终定稿；2026-08-24 用户终审：X-User-Id 全删）**：

| 位置 | 参数 | 必带？ | 功能 |
|---|---|---|---|
| header（客户端配置一次） | `X-API-Key` | **必配** | 鉴权（唯一凭证） |
| tool 参数（每次调用传） | `_AGENT_USERNAME` | 每次必传 | 工号 → operator（沙箱同名环境变量读取） |
| tool 参数（每次调用传） | `_AGENT_SESSION_ID` | 每次必传 | 会话ID → session_id（沙箱同名环境变量读取） |

全部 5 个工具增加两个"上下文参数"，参数名与 Agent 沙箱环境变量**同名**：

| 工具参数 | 沙箱 env 来源 | 落库字段 |
|---|---|---|
| `_AGENT_USERNAME` | 同名环境变量（必存） | telemetry.operator（工号） |
| `_AGENT_SESSION_ID` | 同名环境变量（必存） | telemetry.session_id（**新列**） |

- 工具 description 强制声明"每次调用必须从环境变量读取并传入"，同名映射最大化 Agent 遵从率
- ~~降级链~~：**无 header 降级**（X-User-Id 已整体删除——REST 旧接口同步删除后该机制一并清除）；参数缺则空（统计页 operator 归因显示"?"，可发现未传）
- telemetry 表 `ALTER TABLE ADD COLUMN session_id TEXT DEFAULT ''` + SCHEMA_VERSION bump；聚合新增 by_session（distinct 会话数），skill-usage 明细回带
- 备注：若云平台 MCP 配置支持 header 环境变量插值（`${_AGENT_USERNAME}`），可切换为 header 注入（不依赖 LLM 自觉传参，更可靠）——待用户确认平台能力，当前按传参设计

### 2.3 caller 语义（吸收审查 B1；**2026-08-24 已拍板：新 caller=mcp**）

现状派生规则 `can_frontend → web else skill` 对 MCP 有语义漏洞：
- 若 web 账号（有人用自己账号接 Claude Code）走 MCP，按派生 → caller=web → **取用统计静默归零**（stats 按 caller='skill' 过滤）
- 若硬编码 skill → web 账号被冒记为 skill

**推荐方案**：`/mcp` 通道 caller 恒记新值 **`mcp`**（与传输通道绑定，与用户属性解耦）；统计口径改 `caller IN ('skill','mcp')`——历史 skill 行照常计入，新 MCP 行新口径，人/Agent 两类用户都可见。operator=X-User-Id（有则记）。

## 3. MCP 工具规格（5 个）

工具 description 是 Agent 召回质量的第一决定因素，逐个精心撰写（以下为草案，中文）。

**公共上下文参数（§2.2，5 个工具全部携带）**：`_AGENT_USERNAME`（工号）与 `_AGENT_SESSION_ID`（会话ID）——description 统一附加声明："每次调用必须从环境变量 `_AGENT_USERNAME` / `_AGENT_SESSION_ID` 读取并传入（平台取用统计与追溯用，不影响调用结果）"。下文各工具参数表不再重复列出。

### 3.1 `get_domains` — 业务域入口（原 POST /domains）

- **description 草案**："获取三层图谱全部业务域（BusinessDomain）的完整 markdown。业务域是业务归属的顶层定位层，是任何查询的推荐第一步：先调本工具，按用户需求关键词锁定业务域，再从域 md 的 [[NetworkScenario@*]] 引用下钻场景/方案。返回量小（业务域数量少），可放心全量读取。"
- 参数：无
- 返回：`[{id, name, md}]`（md 含 frontmatter + 正文 + ## 边段）
- 打点：每域一行 `level=object, endpoint=mcp:get_domains, obj_type=BusinessDomain`

### 3.2 `get_md` — 批量取对象 md（原 POST /md，全程主力）

- **description 草案**："按逻辑 ID 批量获取图谱对象的完整 markdown（含 frontmatter + 正文 + ## 边段）。ID 格式：业务层 2 段 {Type}@{slug}（如 NetworkScenario@charging）；NF 类 3 段 {nf}@{Type}@{name}（如 UDG@AtomTask@SET UPDEFAULTQUOTA，name 可含空格）。不传 version 则每个 id 各取最新现存版本。部分失败容错：不存在/版本缺失的 id 单独计错并回带 available_versions，其余 id 照常返回。读完 md 后应提取全文 [[ID]] 引用继续下钻。单次最多 100 个 id 且总量 ≤2MB，超限会报错，请分批。"
- 参数：`ids: string[]`（必填，1~100）、`version?: string`
- 返回：`{id: {version, md} | {error, available_versions}}`
- **体量护栏（吸收审查 F1）**：ids ≤ 100 **且** 响应总字节 ≤ 2MB——超限整单报错（MCP isError，非部分截断），错误信息指引分批。防止单次 tool result 撑爆 Agent 上下文
- 打点：每成功 id 一行 `level=object, endpoint=mcp:get_md, obj_id, obj_type`

### 3.3 `search_objects` — 元数据搜索（原 GET /objects 能力）

- **description 草案**："按关键词搜索图谱对象的元数据（匹配 id / name / name_zh，不搜正文）。支持按层（命令层/特性层/任务层/业务层）、类型、网元、版本、业务域过滤。用于：已知大致名称/编号时定位对象 ID，或浏览某层某网元的对象清单。要搜正文内容请用 search_md。"
- 参数：`q?: string`、`layer?/type?/nf?/version?/domain?/scenario?`、`page?=1 / size?=50`
- 返回：`{total, rows: [{id, type, layer, nf, domain, scenario, name, versions[]}]}`（按 id 聚合，多版本合并）
- 打点：`level=tool`（见 §5）

### 3.4 `search_md` — 正文全文搜索（**新能力**）

- **description 草案**："全文搜索图谱所有对象的 markdown 正文（含参数说明、约束、配置方法等正文内容），按相关度排序返回摘要片段。用于：①用户意图式召回——不确定对象 ID 时按业务关键词找相关 md；②查某个参数/命令/特性名出现在哪些对象里。返回的是片段摘要不是全文，选中后再用 get_md 取完整 md。支持层/类型/网元/版本过滤。默认只搜每个对象的最新版本。"
- 参数：`q: string`（必填）、`layer?/type?/nf?/version?`、`limit?=20 / offset?=0`
- 返回：`{total, hits: [{id, type, name, score, snippet}]}`；snippet 高亮片段（`【】` 包裹命中词，约 48 字符窗口）
- **版本语义（吸收审查 C6）**：默认只搜每个 id 的**最新现存版本**——实现为 FTS 命中行 join 最新版本集过滤（最新版不含关键词则该 id 天然不出现，非"分组后错位取最新"）；传 version 锁定
- 打点：`level=tool`

### 3.5 `get_object` — 单对象结构化 + 出边

- **description 草案**："获取单个图谱对象的结构化详情：frontmatter 元数据、正文、出边列表（from/relation/to）。需要看对象的关联关系（如某 FeatureTask 引用了哪些命令）时用。⚠ 出边仅含 curated 边（## 边段声明显式边），完备遍历必须读 md 全文提取 [[ID]] 引用。要完整原文用 get_md。"
- 参数：`id: string`、`version?: string`
- 返回：`{id, type, layer, scope, nf, version, domain, scenario, frontmatter, body_md, source_path, versions[], out_edges[]}`
- 打点：`level=tool`

## 4. FTS5 正文搜索设计（D3）

### 4.1 表结构

```sql
CREATE VIRTUAL TABLE IF NOT EXISTS md_fts USING fts5(
  obj_id UNINDEXED, version UNINDEXED, body,
  tokenize='trigram'
);
```

- **独立虚拟表**（非 external content）：objects 表是 WITHOUT ROWID，external-content 方案依赖 rowid 不适用；代价是双份正文存储（当前 7k×~10KB ≈ 70MB，可接受）
- **trigram 分词**：中英文统一子串语义；`SCHEMA_VERSION` bump + 显式存量回填迁移（吸收审查 F4，不依赖启动对账隐式兜底）
- 本地验证：SQLite 3.45.3，trigram 建表/查询 OK；启动自检 fail-fast（目标机 <3.34 或未编 FTS5 → 启动报错 + 运维文档）

### 4.2 同步点（吸收审查 C1——按 source_path 级旧集合删）

| 入口 | FTS 动作 |
|---|---|
| `reindex_path`（单文件重索引） | **先取该文件"变更前 (id,version) 旧集合"（delete_by_source 返回值）删 FTS，再插新 (id,version)**——文件内 id/版本变更时不留幽灵行 |
| `unindex_path`（文件消失） | 按该 source_path 关联的 (id,version) 集合 DELETE |
| `rebuild`（全量重建） | 清空 md_fts 重灌 |
| 启动对账 | `COUNT` + `SUM(length(body))` 双校验（吸收审查 C4）；不一致 → **异步后台重建**（不阻塞 lifespan），重建期间 search_md 返回明确错误"索引重建中"（吸收审查 C3） |

### 4.3 查询

- **MATCH 输入转义（吸收审查 C2，必踩点）**：FTS5 MATCH 有自身语法（`AND/OR/NEAR/*/-/引号`，用户搜 `ADD URR` 含空格直接语法错误）。统一包装为短语查询：`'"' + q.replace('"', '""') + '"'`
- `len(q) >= 3` → FTS MATCH（`bm25()` 相关度排序 + `snippet()` 高亮）
- `len(q) < 3`（如"计费"2 字、`RG`）→ **直接对 md_fts(body) LIKE**——trigram 分词器内建支持 LIKE/GLOB 走 trigram 索引（非全表扫），与 MATCH 同表同索引（吸收审查 C5，修正 v1 的 objects 表 LIKE 回退设计）
- 过滤（layer/type/nf/version）：命中 (id,version) join objects 主键直查取元数据过滤
- 版本语义：join 最新版本集过滤（§3.4）

## 5. 打点设计（吸收审查 A2/B1/B3/B4）

| 层 | 行为 |
|---|---|
| request 级 | ASGI 鉴权中间件在**鉴权通过后立即**记 `level=request, endpoint=/mcp, caller=mcp` |
| tool 级（**新增 level 值**） | **每个工具每次调用**记一行：`level=tool, endpoint=mcp:{工具名}, caller=mcp, user, operator, session_id`——search 类工具的使用量从此可观测（v1 设计里 request 级全是 /mcp 无法区分工具，审查 B3） |
| object 级（取用统计口径） | 仅 `get_md`（每成功 id 一行）与 `get_domains`（每域一行）：`level=object, caller=mcp, endpoint=mcp:get_md / mcp:get_domains, obj_id, obj_type, user, operator, session_id` |
| 统计口径 | `aggregate_stats` / `list_skill_usage` 过滤条件改 `caller IN ('skill','mcp')`；`_STATS_ENDPOINTS` 扩为 4 值；**两处 SQL `IN (?,?)` 占位符写死改为动态生成**（审查 B4——不改必抛参数数量错）；聚合新增 `by_session`（distinct session_id 计数）；skill-usage 明细 events 回带 `session_id` |
| 历史连续性 | 旧 endpoint 值 `/md`、`/domains` 保留在 _STATS_ENDPOINTS——30 天窗口内历史行无缝计入；session_id 列对历史行为 ''（新列默认值） |

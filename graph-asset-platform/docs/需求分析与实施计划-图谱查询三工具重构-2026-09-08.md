# 需求分析与实施计划——图谱查询三工具重构（MCP + REST 同步）

> 日期：2026-09-08  
> 状态：**可直接开发**  
> 目标读者：负责 `graph-asset-platform` 后端、MCP、测试和文档更新的开发 Agent  
> 用户已确认：MCP 对外收敛为 3 个工具；`get_domains` / `get_md` 的变更必须同步到 REST `POST /domains` / `POST /md`。

---

## 0. 执行摘要

当前 MCP 暴露 5 个工具：`get_domains`、`get_md`、`search_objects`、`search_md`、
`get_object`。本次重构后，新 Agent 在 `tools/list` 中只看到：

1. `get_domains`：业务域入口。
2. `search_graph`：统一搜索 ID、名称和 md 正文，只负责定位候选 ID。
3. `get_md`：按准确 ID 批量读取权威完整 md，同时返回必要的结构化元数据和全文引用。

合并关系：

| 现有工具 | 目标去向 |
|---|---|
| `search_objects` | 合并到 `search_graph` |
| `search_md` | 合并到 `search_graph` |
| `get_object` | 结构化元数据并入 `get_md`；curated `out_edges` 不再作为 Agent 主路径 |

核心调用路径必须缩短为：

```text
业务方案定位：get_domains → get_md
不知道 ID：search_graph → get_md
已经知道 ID：get_md
```

本次不是只改工具文案。必须同时完成：搜索语义、输入/输出 schema、动态字段校验、
错误模型、MCP/REST 共用业务实现、遥测、旧工具迁移、测试和两套 SKILL 文档更新。

## 1. 背景与现状证据

### 1.1 用户现场现象

2026-09-08 telemetry 摘要中，同一类查询出现：

- `search_md(q="计费防欺诈")` 返回 28 条；
- `search_md(q="计费欺诈 免费流量 免费RG 免费RatingGroup")` 返回 0；
- `search_objects(q="AFUSRDETECT")` 返回 4 条；
- `search_md(q="AFUSRDETECT 计费欺诈用户检测")` 返回 0；
- `search_objects(q="N2")` 返回 137 条，而 `search_md(q="N2接口配置")` 返回 0。

这证明索引并非整体损坏，而是 Agent 把 `q` 理解成多关键词召回，当前实现却把整个
`q` 当成连续字面短语或连续子串。

### 1.2 当前搜索实现的根因

1. `search_objects`
   - 整个 `q` 只在 `id/name/name_zh` 中做一次连续子串匹配；
   - 不分词，不支持 any/all；
   - `type/nf/version/domain/scenario` 均为精确相等；
   - 非法过滤值和真实无结果都表现为 `total=0`。

2. `search_md`
   - `fts_repo.escape_phrase()` 把整个 `q` 包成一对双引号；
   - 空格不是 OR/AND，而是被纳入连续短语；
   - 长度 `<3` 的查询走 LIKE，其他查询走 FTS5 trigram；
   - 索引只含 `body_md`，不含 ID、frontmatter 和 `## 边`；
   - SQL 计算 `bm25()`，但没有 `ORDER BY bm25(...)`，实际并未保证相关度顺序；
   - 当前 5000 行 cap 在元数据过滤之前，可能造成过滤后假 0。

3. MCP schema
   - 除 `AGENT_USERNAME` / `AGENT_SESSION_ID` 外，业务字段在真实 `inputSchema` 中
     基本只有类型和默认值，没有 description、枚举、最小值或最大值；
   - 5 个工具的 `outputSchema` 当前均为空；
   - 管理员非空 description 会完全替换 canonical 工具描述，可能删除调用契约。

### 1.3 Agent 行为问题

现场失败会话只反复调用 `search_md`，没有完成：

```text
search_graph/search_objects 定位 MMLCommand ID
→ get_md 获取完整 MMLCommand md
→ 读取 CommandParameter 字段范围、枚举和约束
```

搜索结果只能是候选，字段范围必须以 `get_md` 返回的 MMLCommand 完整 md 为准。

## 2. 能力目标

### 2.1 用户可见能力

重构完成后，Agent 应能：

1. 不需要判断“搜元数据还是搜正文”，只调用一个 `search_graph`。
2. 用多个独立关键词查询，不再要求整串连续出现。
3. 明确选择：任一关键词命中（`any`）或全部关键词命中（`all`）。
4. 使用 `N2`、`RG` 等不足 3 字符的关键词参与混合搜索。
5. 从 MCP schema 直接知道字段含义、合法范围、分页规则和下一步。
6. 传错 layer/type/nf/version 时得到结构化错误和合法值，而不是静默 0。
7. 从 `get_md` 一次取得完整 md、对象元数据和全文 `[[ID]]` 引用。
8. 通过 MCP 或 REST 获取 domains/md 时得到相同的业务数据、版本解析、错误和护栏。

### 2.2 非目标

- 不引入向量数据库、Embedding 或 LLM rerank。
- 不修改图谱 md 内容和对象 ID 规则。
- 不新增 REST 搜索接口；`search_graph` 只属于 MCP。
- 不改变 `X-API-Key` 鉴权和 skill 权限体系。
- 不把搜索摘要当作配置生成的权威来源。
- 不直接删除旧 MCP 工具；先隐藏兼容，再按调用量下线。

## 3. 不可变设计决策

1. 对外公开工具固定为 `get_domains`、`search_graph`、`get_md`。
2. 保留现有复数名 `get_domains`，不改为 `get_domain`，避免已有客户端失效。
3. 三个 MCP 工具每次都必须传 `AGENT_USERNAME` 和 `AGENT_SESSION_ID`。
4. `get_domains` 与 REST `/domains` 调用同一个核心业务函数。
5. `get_md` 与 REST `/md` 调用同一个核心业务函数。
6. MCP/REST 只允许传输包装和协议错误表达不同，业务数据不得分叉。
7. `search_graph` 输入使用 `terms[]`，不用模糊含义的自然语言大字符串 `q`。
8. 每个 term 本身是一个字面关键词或短语；例如 `"ADD URR"` 作为数组中的一个元素。
9. `match` 只有 `any` / `all`，默认 `any`。不另设 phrase 模式：传一个多词 term 即表示短语。
10. 搜索同时覆盖元数据（ID/name/name_zh）和正文，Agent 不选择搜索源。
11. 搜索命中后必须 `get_md`；snippet 不得直接用于配置生成。
12. MMLCommand 完整 md 是参数字段范围、类型、枚举、必填和已有约束的权威来源。
13. 所有 schema、范围和错误码由代码固定；管理员只能追加说明，不能覆盖核心契约。

## 5. 公共契约

### 5.1 公共归因参数

| 字段 | 类型 | 必填 | 约束 | 用途 |
|---|---|---|---|---|
| `AGENT_USERNAME` | string | 是 | trim 后 1～64 | telemetry.operator |
| `AGENT_SESSION_ID` | string | 是 | trim 后 1～128 | telemetry.session_id |

要求：

- 两字段必须进入真实 MCP `inputSchema`。
- REST `/domains`、`/md` 使用同名 JSON body 字段。
- 字段不参与鉴权；`user` 仍来自 API Key 属主。
- 输入模型设置 `extra="forbid"` / `additionalProperties=false`，防止字段拼错后被静默忽略。
- schema 示例使用真实格式值，如 `00234567`、`session-20260908-001`，禁止使用
  `"从环境变量读取"` 之类可能被 Agent 原样发送的值。

### 5.2 公共业务错误

```json
{
  "code": "INVALID_FILTER",
  "message": "未知 nf: UAC3000",
  "retryable": false,
  "details": {
    "field": "nf",
    "value": "UAC3000",
    "available_values": ["UDG", "UNC"]
  }
}
```

稳定错误码：

| code | REST | MCP | Agent 行为 |
|---|---:|---|---|
| `UNAUTHENTICATED` | HTTP 401 | HTTP 401 | 停止，检查 KEY |
| `PERMISSION_DENIED` | HTTP 403 | HTTP 403 | 停止，联系管理员 |
| `INVALID_ARGUMENT` | 422 | tool error | 修正字段，不原样重试 |
| `INVALID_FILTER` | 不适用 | tool error | 从 available_values 选择或移除过滤 |
| `INVALID_FILTER_COMBINATION` | 不适用 | tool error | 按条件化 available_values 修正组合 |
| `OBJECT_NOT_FOUND` | `/md` 单项错误 | `get_md` 单项错误 | 用 search_graph 重新定位 |
| `VERSION_NOT_FOUND` | `/md` 单项错误 | `get_md` 单项错误 | 选 available_versions 或省略 version |
| `RESULT_TOO_LARGE` | 413 | tool error | 缩小 ID 批次 |
| `INDEX_REBUILDING` | 不适用 | tool error | 有界等待后重试 |
| `SEARCH_TOO_BROAD` | 不适用 | tool error | 增加过滤或减少 terms 后重试 |
| `TOOL_DISABLED` | 不适用 | tool error | 停止或使用明确替代工具 |
| `INTERNAL_ERROR` | 500 | tool error | 最多重试一次后报告 |

REST 图谱路由错误体固定为：

```text
HTTP <status>
{"error": {GraphError}}
```

仅 `/api/v1/domains`、`/api/v1/md` 的 `RequestValidationError` 转成
`INVALID_ARGUMENT`；其他 FastAPI 路由维持现有行为。鉴权 401/403 同样使用 error envelope。

MCP 工具错误固定表现为 HTTP 200 JSON-RPC result：

```json
{
  "result": {
    "isError": true,
    "content": [
      {"type": "text", "text": "{\"error\":{...GraphError...}}"}
    ]
  }
}
```

`_ConfigurableFastMCP.call_tool` 统一捕获工具参数校验和业务异常，使用
`ToolError(json.dumps({"error": error_model.model_dump()}, ensure_ascii=False))`。若当前 SDK
支持 error structuredContent，可同时填充，但 `content[0].text` 的 JSON 是兼容基线。

`INTERNAL_ERROR` 对外只给固定通用消息和 request/error id，详细异常只写服务端日志，禁止
返回 traceback、SQL 或文件路径。

## 6. 工具一：`get_domains`

### 6.1 用途

业务方案定位入口，一次返回全部 BusinessDomain 完整 md。已经知道准确对象 ID 时不必先调。

### 6.2 MCP 输入

```json
{
  "AGENT_USERNAME": "00234567",
  "AGENT_SESSION_ID": "session-20260908-001"
}
```

### 6.3 公共 DomainItem

```json
{
  "id": "BusinessDomain@business-awareness",
  "type": "BusinessDomain",
  "name": "业务感知",
  "version": null,
  "md": "完整 markdown",
  "references": ["NetworkScenario@charging"]
}
```

`references` 必须从完整 `raw_md` 全文用 `\[\[([^\]]+)\]\]` 提取，去重并保持首次出现顺序。

DomainItem 的 6 个字段全部 required，且 `additionalProperties=false`：`name`、`version`
允许 null；`id/type/md/references` 不允许 null。domains 固定按 id 升序，MCP/REST 共享排序结果。

### 6.4 返回包装

MCP 保持当前 envelope：

```json
{"domains": ["DomainItem..."]}
```

MCP DomainsResponse 只有 required 字段 `domains`，且 `additionalProperties=false`。

REST `POST /api/v1/domains` 为兼容旧客户端继续返回裸数组：

```json
["DomainItem..."]
```

唯一允许的包装差异：

```text
mcp_get_domains_response.domains == rest_domains_response
```

除此之外，字段、排序、最新版本选择和错误必须一致。

### 6.5 打点

- MCP：`caller=mcp`、`endpoint=mcp:get_domains`。
- REST：`caller=skill`、`endpoint=/domains`。
- 每次调用 1 条 `tool`。
- 每个返回域 1 条 `object`。
- 两级都记录相同 `user/operator/session_id`。

## 7. 工具二：`search_graph`

### 7.1 职责

统一搜索元数据和 md 正文，输出候选 ID、匹配原因、摘要和 facets。它不返回完整 md，
也不能作为配置字段的权威来源。

### 7.2 输入模型

```json
{
  "terms": ["计费欺诈", "免费流量", "免费RG", "免费RatingGroup"],
  "match": "any",
  "layer": null,
  "type": null,
  "nf": "UDG",
  "version": null,
  "domain": null,
  "scenario": null,
  "page": 1,
  "size": 20,
  "AGENT_USERNAME": "00234567",
  "AGENT_SESSION_ID": "session-20260908-001"
}
```

| 字段 | 类型 | 默认 | 约束/语义 |
|---|---|---|---|
| `terms` | string[] | — | 必填；1～10 项；每项 trim 后 1～80；去重保序 |
| `match` | `any/all` | `any` | any=任一 term；all=全部 term，位置可分散 |
| `layer` | enum/null | null | 命令层/特性层/任务层/业务层 |
| `type` | string/null | null | 当前 registry 类型；动态校验 |
| `nf` | string/null | null | 自动 trim+大写；按当前图谱动态校验 |
| `version` | string/null | null | 精确版本；不传只搜每个 ID 最新版本 |
| `domain` | string/null | null | frontmatter/path 的 domain slug，精确匹配 |
| `scenario` | string/null | null | scenario slug，精确匹配 |
| `page` | integer | 1 | `>=1` |
| `size` | integer | 20 | 1～50 |

规则：

- `layer` 和 `type` 可同时传，但按交集处理；若 type 不属于 layer，返回 `INVALID_FILTER`，
  不能静默忽略任一字段。
- `type/nf/version/domain/scenario` 非法时返回合法值或最接近建议，不能返回普通 0。
- 若不确定动态过滤值，Agent 应先不传该过滤；成功结果的 facets 会给出可选范围。
- `terms=["ADD URR"]` 表示一个包含空格的完整短语。
- 禁止重新引入一个把全部同义词拼成连续字符串的 `q` 参数。

### 7.3 搜索范围

输入 term 统一执行：`trim → Unicode NFKC → casefold`。长度判断、去重、any/all 计数均使用
规范化后的值；规范化后重复时保留第一个原始 term 作为响应展示值。

新增独立的 `graph_search_fts`（旧 `md_fts` 留给 legacy search_md）：

```sql
CREATE VIRTUAL TABLE IF NOT EXISTS graph_search_fts USING fts5(
  obj_id UNINDEXED,
  version UNINDEXED,
  metadata_text,
  body_text,
  tokenize='trigram'
);
```

- `metadata_text`：规范化后的 id/name/name_zh，以换行连接。
- `body_text`：规范化后的 body_md；原始 body_md 仍在 objects，用于最终 snippet。

每个 term 自动搜索：

| 数据面 | 字段 | 匹配 |
|---|---|---|
| 元数据 | metadata_text，并用原字段判定等级 | 规范化后字面包含 |
| 正文 | body_text | term 长度 ≥3：FTS5 trigram 短语；长度 <3：LIKE 字面包含 |

不搜索 `## 边` 作为正文召回依据；引用关系由 `get_md.references` 提供。

短 term（规范化后长度 <3）最多 3 个，并且 LIKE 必须先限定到 filters + latest 候选；
LIKE 转义 `\`、`%`、`_`。不得宣称不足 3 字符可由 trigram 索引加速。

### 7.4 any/all 合并

对每个 `(id, version, normalized_term)` 合并元数据和正文命中。同一个 term 即使同时命中
多个字段也只计 1 次。随后对每个 `(id, version)` 累积：

- 命中的 term 集合；
- 命中字段集合（id/name/name_zh/body）；
- 最多 3 个正文 snippets（按输入 term 顺序）；
- 每个长正文 term 的 BM25 排名；
- 元数据匹配等级。

`any` 保留命中至少 1 个 term 的对象；`all` 只保留命中全部 term 的对象。

### 7.5 版本和过滤顺序

必须按以下顺序：

1. 规范化并验证 filters。
2. 若指定 version，只搜索该版本；否则限定到每个 ID 的最新版本。
3. 在 SQL 或候选集合阶段先应用 type/layer/nf/version/domain/scenario。
4. 再执行每个 term 的元数据/正文搜索，禁止先截断单 term 结果。
5. 合并 any/all。
6. 排序。
7. 在 any/all 聚合后检查搜索预算。
8. 最后分页。

禁止“全库先取 5000 条、再按 nf/type 过滤”。

为让“最新版”在 term 搜索前生效，新增并维护：

```sql
CREATE TABLE IF NOT EXISTS object_latest (
  id TEXT PRIMARY KEY,
  version TEXT NOT NULL
) WITHOUT ROWID;
```

全量 rebuild、导入、reindex、删除/回退后都要与 objects 同事务刷新受影响 ID 的最新版本。
`object_latest.version` 必须沿用 objects 的 DB 表示：无版本对象使用空串 `""`，API 输出时
还原为 `null`。不得向 NOT NULL 列写 Python `None`。

查询明确分两支：

- 不传 version：join `object_latest ol ON ol.id=o.id AND ol.version=o.version`。
- 显式 version：**不 join object_latest**，只使用 `WHERE o.version=?`，保证旧版本可搜。

刷新函数接收 `old_ids ∪ new_ids`：查询每个 ID 的全部现存版本，使用现有 Python
`latest_version()/is_newer()` 语义选择最新版并 UPSERT；ID 已无任何版本时 DELETE。
禁止用 SQL `MAX(version)`。

### 7.6 排序

长正文 term 的 SQL 必须 `ORDER BY bm25(graph_search_fts)`，并给每个 term 的结果赋
1-based `body_rank`。跨 term 不直接比较 raw BM25，而采用 RRF：

```text
body_rrf = Σ 1 / (60 + body_rank_for_term)
```

短 LIKE term 和纯元数据命中不贡献 body_rrf。元数据等级固定为：

| 等级 | 条件 |
|---:|---|
| 4 | id 完全匹配 |
| 3 | name/name_zh 完全匹配 |
| 2 | id/name/name_zh 前缀匹配 |
| 1 | id/name/name_zh 包含 |
| 0 | 仅正文匹配 |

对象取所有 term/字段中的最高元数据等级。最终稳定排序 tuple：

1. `matched_terms_count` 降序；
2. `best_metadata_level` 降序；
3. `body_rrf` 降序；
4. type、id 稳定升序。

对外不暴露难以稳定解释的浮点 `score`，只返回 `rank_reasons`。不得继续返回一个未参与
排序的 score。

### 7.7 搜索预算、total、分页与 facets

- 禁止 per-term top-K 后再求 all 交集；这会制造假 0。
- 先取得 filters/latest 范围内的完整 term hit ID 集，再 union/intersection。
- 内部最多处理 2,000,000 条 `(term,id,version,field)` 中间命中；超过时整次返回
  `SEARCH_TOO_BROAD`，提示增加 nf/type/layer 等过滤，不返回近似或部分结果。
- 成功响应的 `total` 始终是 any/all 合并、按 `(id,version)` 去重后的精确数量。
- `has_more` 仅表示精确结果在当前页之后仍有记录，`next_page` 无下一页时为 null。
- facets 对“terms/match + 全部 applied filters 后、分页前”的精确结果集合统计；不是合法值
  catalog，也不用于证明被当前 filter 排除的其他值。
- 外部单页最多 50 条，避免撑爆 Agent 上下文。

### 7.8 返回模型

```json

      "id": "UDG@MMLCommand@ADD URR",

      "name": "ADD URR",

      "versions": ["20.15.2", "20.16.0"],

      "matched_in": ["body"],
      "snippets": [
        {"term": "免费RG", "text": "……【免费RG】……"}
      ],
      "rank_reasons": ["正文命中1个关键词"]
```

```json
{

  ]
}
```

恢复建议必须由结构化诊断产生：

- `match=all`、各 term 有单独命中但交集为 0：`USE_MATCH_ANY`。
- 某 term 在当前 filters 下为 0：`REMOVE_OR_REPHRASE_TERM`，details 指出该 term。
- 当前 filters 下为 0，但执行一次“移除全部可选 filters”的有界 count probe 后有命中：
  `RELAX_FILTERS`。
- filter 值非法或组合非法：不进入零结果，分别返回 `INVALID_FILTER` 或
  `INVALID_FILTER_COMBINATION`。

### 7.9 打点

- `caller=mcp`
- `endpoint=mcp:search_graph`
- 只记录 `tool` 行，不记录 `object` 行。
- params：terms、match、filters、page、size，不重复写工号/会话。
- result：total、returned、top_ids、matched_terms_count、recovery_codes。
- 禁止写完整 md 或全部 snippets 到 telemetry。

## 8. 工具三：`get_md`

### 8.1 MCP/REST 统一输入

```json
{
  "ids": ["UDG@MMLCommand@ADD URR"],
  "version": null,
  "AGENT_USERNAME": "00234567",
  "AGENT_SESSION_ID": "session-20260908-001"
}
```

| 字段 | 约束 |
|---|---|
| `ids` | 1～100；item trim 后非空；按去重后数量校验；保持首次出现顺序 |
| `version` | null 或 trim 后非空；全局精确版本 |
| 上下文字段 | 见 §5.1 |

Agent-facing description 建议每批 5～20 个 ID；100 是服务硬上限，不是推荐批量。

### 8.2 共享返回 map

MCP `get_md` 与 REST `/api/v1/md` 必须返回完全相同的 map。

成功项：

```json
{
  "ok": true,
  "id": "UDG@MMLCommand@ADD URR",
  "type": "MMLCommand",
  "name": "ADD URR",
  "nf": "UDG",
  "domain": null,
  "scenario": null,
  "version": "20.16.0",
  "versions": ["20.15.2", "20.16.0"],
  "md": "完整 markdown",
  "references": ["UDG@ConfigObject@URR"]
}
```

对象不存在：

```json
{
  "ok": false,
  "id": "UDG@MMLCommand@NOT EXISTS",
  "error_code": "OBJECT_NOT_FOUND",
  "error": "对象不存在",
  "available_versions": []
}
```

版本不存在：

```json
{
  "ok": false,
  "id": "UDG@MMLCommand@ADD URR",
  "error_code": "VERSION_NOT_FOUND",
  "error": "版本不存在",
  "requested_version": "19.0.0",
  "available_versions": ["20.15.2", "20.16.0"]
}
```

外层继续保持当前动态 ID 键，兼容已有调用：

```json
{
  "UDG@MMLCommand@ADD URR": {"ok": true, "...": "..."},
  "UDG@MMLCommand@NOT EXISTS": {"ok": false, "...": "..."}
}
```

新增字段属于向后兼容扩展；现有 `version` / `md` 和 `error` / `available_versions`
字段不得删除。

字段级契约：

- MdSuccess 全部字段 required 且 `additionalProperties=false`。
- `name/nf/domain/scenario/version` 类型为 `string|null`。
- `versions` 类型为 `string[]`；无版本对象固定返回 `[]`，不得返回 `[null]`。
- `md` 为非空 string；`references` 为 string[]。
- MdFailure 全部字段 required 且 `additionalProperties=false`；`requested_version` 允许 null。
- 外层 map key 使用 trim 后的规范 ID；ID 内部空格保留。同一规范 ID 重复时只保留首次位置。

### 8.3 outputSchema

使用 Pydantic `RootModel[dict[str, MdSuccess | MdFailure]]` 或等价 JSON Schema：

- `additionalProperties` 是 `oneOf(success, failure)`；
- success.required 包含 §8.2 列出的全部 MdSuccess 字段；
- failure.required 包含 §8.2 列出的全部 MdFailure 字段。

必须用真实 `tools/list` 测试确认 FastMCP 输出非空 `outputSchema`；不能只写 Python 类型但
不验证协议结果。若当前 FastMCP 不能从 RootModel 自动生成，优先使用等价 TypedDict 或
在工具注册层显式提供 output schema；不得仅为生成 schema 改掉现有动态 ID map wire shape。

### 8.4 共享护栏

以下逻辑全部进入 `get_md_core()`，MCP 与 REST 不得各自实现：

1. ids 去重保序；
2. 去重后 1～100；
3. 全局 version 解析；
4. 每 ID 部分失败；
5. references 全文提取；
6. 对完整业务 map 做确定性 JSON 序列化后累计 UTF-8 字节；
7. 总响应 2 MB 上限；
8. 结构化结果构造。

REST 当前缺少 100 IDs 和 2 MB 护栏，本次必须补齐。超限行为：

- REST：HTTP 413 + `RESULT_TOO_LARGE`；
- MCP：tool error + 同一错误对象。

唯一计量函数放在 core：

```python
payload_bytes = len(json.dumps(
    result_map,
    ensure_ascii=False,
    separators=(",", ":"),
).encode("utf-8"))
```

计算包含动态 ID key、metadata、md、references 和失败项，不包含 MCP JSON-RPC 或 HTTP
传输包装。`payload_bytes <= 2*1024*1024` 成功，严格大于时整单失败。整单通过护栏后 adapter
才写 object telemetry，防止最终失败却留下“成功取用”对象点。

### 8.5 `get_object` 能力吸收

`get_md` success 已包含：id/type/name/nf/domain/scenario/version/versions/md/references。
Agent 不再需要 `get_object`。

不把 curated `out_edges` 搬入新结果作为完备关系来源；若后台 UI 仍需要结构化边，继续使用
现有 REST 对象接口，不作为公开 MCP 主路径。

### 8.6 打点

| 通道 | caller | endpoint |
|---|---|---|
| MCP | mcp | `mcp:get_md` |
| REST | skill | `/md` |

- 每次调用 1 条 tool 行；每个成功 ID 1 条 object 行。
- 失败 ID 不写 object 行。
- params/result 摘要字段对齐：`ids/version`、`ok/failed/failed_ids/bytes`。
- 除 caller/endpoint 外，MCP 与 REST 的 user/operator/session_id 和摘要语义一致。

## 12. 数据库与 Repository 改动

### 12.1 新增 `object_latest`

见 §7.5。要求：

- `init_schema` 幂等创建；
- DB 中无版本统一存空串 `""`；API 模型再还原为 null；
- 首次迁移从 objects + 现有 Python 版本比较逻辑回填，禁止 SQL MAX；
- 全量 rebuild 后重建；
- 单文件 reindex/delete/rollback 使用 `old_ids ∪ new_ids` 刷新；
- 删除当前最新版后自动降级到次新；删除最后版本后删除 latest 行；
- `reindex_paths` 按现有 chunk 累积 affected_ids，每个 chunk 批量刷新一次；
- 事务与 objects/FTS 更新保持一致；
- 增加完整性检查：每个 objects.id 恰好一个 latest 行，version 必须实际存在。

### 12.2 新统一搜索索引与 Repository

新增 `graph_search_fts`，旧 `md_fts` 在 legacy 周期内保留。写入时统一使用
`normalize_search_text()`（trim/NFKC/casefold），同时维护 metadata_text/body_text。

Repository 接口固定为：

```python
search_metadata_term(
    term: NormalizedTerm,
    filters: SearchFilters,
) -> MetadataTermHits

search_body_term(
    term: NormalizedTerm,
    filters: SearchFilters,
) -> BodyTermResult
```

要求：

- metadata term 先在 graph_search_fts.metadata_text 定位候选，再读取 objects 的
  id/name/name_zh 判定固定匹配等级；name_zh 来源为 frontmatter_json；
- body term ≥3：`graph_search_fts MATCH ?`，使用 column filter 限定 body_text；
- body term <3：对 body_text 做 `LIKE ? ESCAPE '\\'`；短词最多 3 个；
- 不传 version 时 join object_latest；显式 version 时不得 join latest；
- join objects，并在 term 命中结果产生前应用 layer/type/nf/version/domain/scenario；
- 长正文 term 必须 `ORDER BY bm25(graph_search_fts)` 并返回 1-based rank；
- 不做 per-term LIMIT；累计中间命中超过 2,000,000 时抛 SEARCH_TOO_BROAD；
- SQL 全部参数化，禁止拼接 filter 值。

SQLite FTS5 函数使用真实表名：`graph_search_fts MATCH ?`、
`bm25(graph_search_fts)`，禁止把 table alias 直接传给 MATCH/bm25。

补充索引并用 `EXPLAIN QUERY PLAN` 验证实际查询：

```sql
CREATE INDEX IF NOT EXISTS idx_objects_nf_type_version
  ON objects(nf, type, version);
CREATE INDEX IF NOT EXISTS idx_objects_domain_scenario
  ON objects(domain, scenario);
```

是否增加更多索引必须以真实 explain/基准结果为依据，不盲目堆索引。

### 12.3 动态 catalog

合法值的 source of truth：

1. 当前 objects 实际 distinct 值是 nf/version/domain/scenario/type 的主来源；
2. type→UI layer 使用 `ui_layer_of` / UI_LAYER_TYPES；
3. registry 只补充当前零实例但合法的扩展 type，不覆盖实际数据；
4. 若 nf 仅大小写不同却出现多个 canonical 值，返回数据完整性错误，不可任选。

`catalog.py` 提供：

- canonical layers；
- types 及所属 layer；
- nfs；
- versions_by_nf；
- domains；
- scenarios_by_domain。

用途：输入校验、INVALID_FILTER.available_values、零结果建议和 search facets。它是内部服务，
不新增第 4 个公开工具。

校验规则：

- 单个值全局不存在：`INVALID_FILTER`。
- nf/version、domain/scenario、layer/type 等值分别合法但组合无对象：
  `INVALID_FILTER_COMBINATION`，返回当前上游过滤条件下的条件化 available_values。
- filters 合法且组合存在，但 terms 无命中：才返回正常 `total=0`。

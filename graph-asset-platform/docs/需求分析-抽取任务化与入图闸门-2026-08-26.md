# 需求分析：抽取任务化与入图闸门（2026-08-26）

> 取代 2026-08-19《两步流水线与可插拔解析器》中的步骤②（模式+范围+force）设计。
> 步骤①（产品文档解压）**不变**。

## 1. 背景与痛点

现状「自动抽取」与产品文档包强耦合：

- 上传归档时定死 (nf, version)，抽取的资产**永远**落包自身的槽位
  `assets/{层}/{nf}/{version}` ——一份产品文档内含多网元命令时，只能把同一归档
  重复上传多次（存储翻倍、转换重复）；
- 入库直接写资产目录：无差异审查、无按任务回退（质量不行只能手工清理）；
- 「模式」捆绑 4 个构建器 + 范围勾选 + 依赖自动补选，任务边界模糊。

## 2. 目标模型

```
产品文档包（解压一次 = 原始知识，物理网元+版本只作管理标识）
   ├─抽取任务A：脚本①命令+配置对象 → 目标 UDG@20.15.2
   ├─抽取任务B：脚本①命令+配置对象 → 目标 AMF@20.15.2（目标可异于包名）
   ├─抽取任务C：脚本②License        → 目标 UDG@20.15.2
   └─抽取任务D：脚本③Feature        → 目标 UDG@20.15.2（依赖 A、C 完成；自动重跑命令补引用）
```

任务生命周期六段：**选输入 → 依赖校验(阻断) → 沙箱构建 → 入库门禁 → 入库 → 留痕(可回退)**。

## 3. 用户决策（2026-08-26 拍板，全量）

| # | 决策点 | 结论 |
|---|---|---|
| D1 | 解压 | **不动**：物理网元+版本=包管理信息+抽取默认值 |
| D2 | 目标网元/版本 | 抽取时输入，默认=包的、**必可改**（图谱逻辑网元名由用户定） |
| D3 | 依赖 | **阻断式**：目标槽位缺 needs 层 → 400 报明细，不自动补齐；人来编排「先命令后特性」 |
| D4 | 入库门禁 | 入库前报告：纯新增 X（分层）/ 内容一致 Y / 有差异 Z（每文件 ±行数或字节数）→ 三选：**一键覆盖 / 只新增（重复保留现有）/ 撤销（无痕）** |
| D5 | 任务留痕 | 产物清单（路径+op+sha256）→ 支持按任务移除；sha 守卫防误删后续任务的覆盖 |
| D6 | force | **退场**：整层清空语义删除（旧文件清理→按任务移除；重抽覆盖→门禁覆盖） |
| D7 | Feature→Command 引用 | **保持现状 two_pass 语义不拆分**：Feature 任务自动重跑命令+配置对象构建器（用最近一次成功 cmd 任务记录的源目录），Command 层变化进门禁报告；旧数据无记录则跳过并警告 |
| D8 | 任务粒度 | **单脚本单任务**（要多个脚本=多个任务） |
| D9 | 脚本接入 | **后台预制注册**（非前端上传）；脚本=规范拷贝件**零改动**（已验证脚本对 --storage 无相对路径假设） |

三个预制抽取器：①`cmd`=命令+配置对象（永远整体）②`license` ③`feature`（needs
Command+License；rerun_after=命令+配置对象）。

## 4. 关键架构决策：沙箱门禁（vs 资产内快照）

**选定：沙箱**。构建脚本 `--storage` 指向 `DATA_DIR/.extract_gate/{job_id}/storage/`
（沙箱 assets 根），先预拷目标 (nf,version) 已存在的层（`Builder.reads` 并集——跨层读
在沙箱闭环 + 命令分次累积时旧命令在场）。确认时才把变更文件拷入正式资产 + 增量索引。

否决**快照法**（先备份正式层目录→脚本直写→diff→按选择回补）的理由：

1. 资产目录出现未确认内容 → 重启时 `_sync_mtime_async` 会把它们索引进库（静默提交）；
2. cancel 需"删新增+还原修改"两步逆向操作，失败模式多；
3. 快照若放 assets 内会被 `store.list_md()`（rglob 不过滤隐藏目录）扫到。

沙箱模型的代价（已接受）：每任务一次目标层 copytree（设计态秒~十秒级）、
`build_features` 读自身输出的脏目录膨胀语义与线上一致（未改变）。

## 5. 状态机与持久化

```
processing ──→ awaiting ──confirm(overwrite|new_only)──→ done ──revert──→ done(reverted_at)
    │             │
    │             └─cancel──→ cancelled（终态）
    └─失败/重启 sweep──→ failed（沙箱被 sweep_orphan_gates 清）
```

- `awaiting` **非终态**：跨重启存活（`sweep_interrupted` 只清 processing）；期间 kind
  互斥已释放（其他目标可继续抽），但**同目标**再发起 409（沙箱/报告单份）。
- job 的 nf/version 列 = **目标**网元/版本；包身份在 result（bundle_nf/bundle_version）。
- `extract_files` 表（db v9）：产物清单 (job_id, path, op, sha256, layer)。
- 回退权依赖 originals 备份（盘）+ extract_files（库）——**删除任务历史即丧失**（UI 删除时提示）。

## 6. 门禁报告与回退算法

**diff**（沙箱 vs 正式，逐 written 层）：`_` 前缀 sidecar（`_build_manifest.json`，
built_at 每次必变）只静默同步不进报告；无→新增；sha 同→一致；异→modified
（.md/.txt 计 ±行数 difflib；二进制记 old/new 字节数；明细截 500，总数存真值）。

**apply 以磁盘实时重分类为准**（报告仅参考）：新增→copy；一致→跳；modified→
overwrite 先备份旧版到 `originals/{job_id}/` 再覆盖 / new_only 跳过。manifest 记
应用后内容 sha256。锁序：router 持 kind 互斥 → apply 内 import_lock 做索引段（与
历史 run_mine 相同，无反向路径）。

**revert**：逐清单行 sha 守卫（磁盘 ≠ 记录 → 跳过防误删）；add→`store.soft_delete`
进回收站（trash 表登记）；modify→还原 originals 旧版；受影响层前缀增量重索引。

## 7. API（/api/v1/import，写端点二次校验 can_assets）

| 端点 | 说明 |
|---|---|
| `GET /extractors` | 抽取器下拉（id/name/needs/roles/required_roles/rerun） |
| `GET /target-assets?nf=&version=` | 目标四层资产存在性（依赖检查 UI） |
| `GET /bundles/{nf}/{ver}/locate?extractor=&target_nf=` | 目录定位（**target_nf 严格匹配**） |
| `POST /extract` | 发起任务；400（名/extractor/包未就绪/必选角色/**依赖缺失 detail.missing**）；409（互斥忙/同目标 awaiting） |
| `POST /extract/{job}/confirm` | `{action: overwrite\|new_only}`（同步端点，秒级） |
| `POST /extract/{job}/cancel` | 撤销（终态 cancelled） |
| `POST /extract/{job}/revert` | 按任务移除产出（sha 守卫） |

删除：`GET /import/modes`、`POST /import/mine`（模式/范围/force 全退场）。

## 8. 已知限制（接受）

- **跨批次参见边**：build_commands 规范要求全部 `--mml-dir` 单次调用（两趟名集校验），
  命令分两次任务抽时跨批参见边会缺——同任务多选目录可避免（现状同款限制，前端已提示）；
- build_features 读自身输出目录（沙箱同拷）→ 旧脏目录膨胀有效码集，与线上语义一致；
- awaiting 任务占用的目标槽位不能并发再抽（阻断 409，语义正确而非性能问题）。

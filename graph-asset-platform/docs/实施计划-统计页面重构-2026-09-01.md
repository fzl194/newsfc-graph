# 实施计划：统计页面重构（三视图统计）

> 日期：2026-09-01 ｜ 需求权威：《图谱平台统计页面需求说明书（外部Agent版）.md》v1.0（仓库根目录）
> 状态：已实施完成（本文档为落地记录：实现决策、端点清单、验收映射、部署注意事项）

## 1. 背景与结果

统计页从"按 UI 层聚合的内存索引卡片"重构为**三 Tab 统计视图**（命令图谱 / 特性图谱 / 业务图谱），
数据源改为 platform.db 只读 SQL 聚合（objects/edges + 8 张 AIMML 历史规则表），支持多维筛选与
CSV/Excel/Markdown 导出。旧 `GET /api/v1/stats` 保留（AppHeader 头部计数 / LayerNav 下拉 /
UploadView 提示仍依赖）。

## 2. 实现决策（用户授权开发 Agent 自主拍板，2026-09-01）

| 决策点 | 结论 | 依据 |
|---|---|---|
| 8 张规则表建表 | db.py v11 幂等 CREATE（DDL 与需求书 §9 逐字一致）+ 索引 | 本地库无表；内网由 dump 脚本灌数 |

| B1 双口径 | 卡片显全局 DISTINCT；另给"分组求和口径"（同命令跨 (NE,版本) 重复计） | Case 1 全局 35,051 ≠ §5.1 分组求和 |
| 下钻分页 | GROUP BY 结果 ≤ 数百行，不分页，前端排序 | KISS |
| TelemetrySection | 保留页面底部（打点统计不在本次重构范围） | 不删既有能力 |
| 图表 | 本期不做（需求只要求卡片+明细表+导出） | YAGNI |

## 6. 部署注意（内网）

1. `git pull` + 重启即完成 schema v11（幂等建 8 张空表；platform.db 其余不动）。
2. 8 张 B_AI_* 表数据由内网 GaussDB 导出脚本灌入：
   `AIMML历史图谱/db_tool/dump_rule_tables_to_platform.py`（需求书配套，内网已具备；
   若 platform.db 已含数据则只需重启）。**未灌数时**统计页命令图谱的命令/参数/五类规则
   指标为 0，页面顶部会出现"规则表未导入"提示条。
3. 运行环境需 SQLite ≥ 3.38（`json_extract` 提取 feature_code/license_code；
   Python 3.11+ 自带的 sqlite 均满足）。
4. 验收：对需求书 §11 各 Case SQL 在内网库复跑，页面/导出数字应逐一一致
   （A5 口径差异见 §2 决策表——跨图谱入边）。

### 8.4 口径勘误（2026-09-02 用户复核）

语法规则统计总表中语法行的「规则数量」原先填了语法表行数，与「参数数量」恒等（用户指出
"参数数量和规则数量一致肯定是错的"）。**语义上语法表没有独立的规则数量口径**（其行=参数
定义），修正为：语法行规则数量置 0（前端显示 —），三个计数列头加口径 tooltip——

- 命令数量（B1）= 语法规则表 `COUNT(DISTINCT CMD_NAME)`（组内去重）
- 参数数量（B2）= 语法规则表行数（每行 = 一条命令参数定义）
- 规则数量 = 五类规则表（图/重复/MOD/SET/删除）行数；语法行无此口径

连带修复：`_sort_rows` 的 `r.get(f) or ""` 会把 0 变字符串与 int 混比抛 TypeError——
排序键改三元组类型归一（数值列出现 0 的场景由此出现，如语法行 rule_count=0）。
pytest 366 绿。

### 8.5 第三轮改版（2026-09-02 深夜，缓存化 + 规则长表）

| 反馈 | 决策 |
|---|---|
| 筛选仍卡（百万行） | **cache.py 预聚合缓存**：启动后台预热全量聚合 + 「更新缓存」按钮重建（POST /stats/cache/refresh，构建期间服务旧数据、完成原子换新，reset 带代数守卫防测试竞态）；筛选在内存聚合行上过滤，**DISTINCT 指标缓存集合（set），任意粒度由并集推导不再回表**；MOP 不走缓存（文件随时换） |

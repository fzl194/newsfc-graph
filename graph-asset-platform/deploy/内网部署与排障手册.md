# 图谱平台内网部署与排障手册

> 更新：2026-09-03 ｜ 适用镜像：`gap-image-20260903.tar` 及之后版本
> 原则：**代码全在镜像里，数据全部外挂**（platform-data 一个目录 = 平台全部状态）

---

## 1. 部署三件套

| # | 文件 | 说明 |
|---|---|---|
| ① | `gap-image-<日期>.tar` | 镜像包（约 73MB，含前后端 + MCP + 兼容接口 + 统计页全功能） |
| ② | `docker-compose.image-only.yml` | 80 端口、纯镜像运行、只挂数据 |
| ③ | `platform-data/` 整目录 | 数据（见 §2）；以内网服务器现有数据为底准备 |

## 2. 数据目录（platform-data/）

| 内容 | 必需 | 说明 |
|---|---|---|
| platform.db | ✅ | 索引/用户/任务/打点 + 8 张 B_AI 规则表（灌数后） |
| assets/ | ✅ | 图谱资产 md（没有它图谱浏览全空） |
| output/ | 建议 | 原始文档包（抽取任务历史；不带则历史任务列表清空） |
| mop_scenarios.xlsx | 可选 | MOP 底表；也可管理员页面上传 |
| stats_overview.json | 可选 | 统计页进展总览配置；也可管理员页面编辑 |
| users.json / tests/ / telemetry/ / .extract_gate/ | 可选 | 其他状态 |

注意：admin 登录 KEY 以 platform.db 里的 users 表为准（整库替换后用源库的 KEY）。

## 3. 部署步骤

```bash
# ① 载入镜像
docker load -i gap-image-20260903.tar

# ② 停旧服（如有）
cd /路径/graph-asset-platform/deploy
docker compose down 2>/dev/null; docker stop gap 2>/dev/null; docker rm gap 2>/dev/null

# ③ 换数据（留后手再覆盖）
mv platform-data platform-data_backup 2>/dev/null
# ← 上传新的 platform-data 到当前目录

# ④ 起服（两种方式二选一）
```

**方式 A：compose（推荐）**——`docker-compose.image-only.yml` 放在 deploy/ 下：

```bash
docker compose -f docker-compose.image-only.yml up -d
```

**方式 B：裸 docker run**（服务器没有 compose 插件时用，效果等价）：

```bash
docker run -d --name gap --restart unless-stopped -p 80:80 -e GAP_DATA_DIR=/data -v $PWD/platform-data:/data graph-asset-platform:latest python -m uvicorn app.main:app --host 0.0.0.0 --port 80
```

> ⚠️ 铁律：`-p` `-e` `-v` `--name` 等 docker 参数必须在**镜像名之前**；`python -m uvicorn ...`
> 是容器内命令，放**镜像名之后**。端口映射创建时定格，**事后改不了**，要改只能删容器重建。

**⑤ 验证**：

```bash
docker logs -f gap        # 看到以下三行即成功（Ctrl+C 退出日志）
#   [startup] 统计缓存后台预热中（数据量大时约几十秒）…
#   [startup] MCP 服务就绪 → /mcp
#   INFO: Uvicorn running
```

浏览器开 `http://<服务器IP>/`（80 端口不用写端口号）。

**验收四步**：admin 登录 → 统计页三 Tab 有数（规则表有数=B_AI 灌数成功；全 0+顶部黄条=没灌）→ 图谱浏览有对象 → 业务图谱 MOP 出统计。

## 3.5 日常升级：代码同步（不再传镜像包）

镜像只当**运行时**（python+依赖），代码外挂后日常升级只需传 2~3MB 的代码包：

```bash
# ① 外网机（打包：自动构建前端 + 打 backend/app + frontend/dist）
cd graph-asset-platform
bash deploy/sync.sh pack
# → 生成 gap-sync-<日期>.tar.gz + .sha256（两个文件一起传内网）

# ② 内网（在 graph-asset-platform/ 目录下；自动校验→原子换代码→重建容器）
bash deploy/sync.sh apply /路径/gap-sync-xxxx.tar.gz

# 其他：
bash deploy/sync.sh restart    # 仅重建容器（不动代码/数据）
bash deploy/sync.sh logs       # 看日志
```

- 数据目录（deploy/platform-data/）永不触碰
- 代码替换是"备份→换新→清备份"原子操作，中断自动回滚
- **依赖变更提醒**：包内带 pyproject.toml/package.json 基线，apply 检测到变化会
  警告"需重新导全量镜像"（pip/npm 装新包的场景才需要，日常改代码不会触发）
- 容器内固定 8000、宿主机端口默认 80（改端口：`GAP_PORT=xxx bash deploy/sync.sh apply ...`）

## 4. 排障决策树（外部访问不通时）

**链路：容器内 → 宿主机 → 局域网。从左往右逐段排查，哪段断了修哪段。**

### 第一段：容器内自测

```bash
docker exec -it gap bash
# 容器内（slim 镜像无 curl，用 python）：
python -c "import urllib.request as u; r=u.urlopen('http://127.0.0.1:80/', timeout=3); print('容器内 OK', r.status)"
exit
```

- ✅ 200 → 服务正常，**直接进第二段**（下面查端口的分支只在自测失败时用）
- ❌ 拒绝 → 查真实监听端口（容器内单行，⚠ 别用 awk strtonum——镜像里是 mawk 没这函数）：
  ```bash
  python -c "print(sorted({int(l.split()[1].split(':')[1],16) for l in open('/proc/net/tcp').read().splitlines()[1:] if l.split()[3]=='0A'}))"
  ```
  输出即监听端口（十进制）。端口对不上（如服务在 8000 你测了 80）→ 按真实端口重测；完全没有 → `docker logs --tail 50 gap` 看崩溃堆栈

### 第二段：端口映射 + 宿主机自测

```bash
docker ps --filter name=gap        # PORTS 列必须看到 0.0.0.0:80->80/tcp
docker port gap                    # 应输出 80/tcp -> 0.0.0.0:80
ss -ltnp | grep ':80 '             # 宿主机 80 在监听（docker-proxy）
curl -I http://127.0.0.1/          # 期待 HTTP/1.1 200 OK
```

- PORTS 列空 / docker port 无输出 → 启动时没带 `-p`（或 `-p` 写到了镜像名后面被当命令吞了）→ **删容器重建**（§3 方式 B 那条完整命令）
- `ss` 查不到 80 → `systemctl restart docker && sleep 10`（重建转发规则）再查
- 本机 curl 通、局域网不通 → 第三段

### 第三段：防火墙 / SELinux

```bash
# firewalld（CentOS/RHEL）
systemctl is-active firewalld && firewall-cmd --add-port=80/tcp --permanent && firewall-cmd --reload

# ufw（Ubuntu）
ufw allow 80/tcp

# 兜底 iptables
iptables -I INPUT -p tcp --dport 80 -j ACCEPT

# SELinux（CentOS 可能拦 docker 转发）
getenforce                     # 输出 Enforcing 则：
setenforce 0                   # 临时放行验证；确认是它后永久：
# sed -i 's/^SELINUX=enforcing/SELINUX=permissive/' /etc/selinux/config
```

改完在办公机 `curl -I http://<服务器IP>/` 验证。

## 5. 常用运维命令

```bash
docker exec -it gap bash                  # 进容器终端（exit 退出，容器不受影响）
docker logs -f gap                        # 实时日志
docker logs --tail 50 gap                 # 最后 50 行（排崩溃）
docker restart gap                        # 重启容器（数据在外部，安全）

# 看容器的实际启动配置（命令/映射/挂载/环境变量）
docker inspect gap --format 'Cmd={{.Config.Cmd}}
Ports={{.HostConfig.PortBindings}}
Binds={{.HostConfig.Binds}}
Env={{.Config.Env}}'

docker cp gap:/data/platform.db ./        # 容器内外互拷文件
docker ps -a --filter name=gap            # 看是否残留 Exited 的旧容器（易串，rm 掉）
```

## 6. 升级 / 数据变更流程

**换新版本镜像**：`docker load -i 新.tar` → `docker rm -f gap` → 用 §3 同一条命令重跑（platform-data 不动，数据自动沿用）。

**图谱数据变更后**：统计页右上点「**更新缓存**」按钮即可（不必重启）；重启容器也会自动重建缓存。

**备份**（停服后打包才保证 SQLite 一致）：

```bash
docker stop gap && tar czf gap-backup-$(date +%F).tgz platform-data && docker start gap
```

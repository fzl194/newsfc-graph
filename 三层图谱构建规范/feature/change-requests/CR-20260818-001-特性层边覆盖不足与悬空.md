# CR-20260818-001-特性层边覆盖不足与悬空

## 场景
用户要求在平台上传 pipeline 前核查特性层边（尤其特性↔特性）。用临时扫描脚本（output/_scan_featurerefs.py）对 UDG（258 特性）+ UNC（470 特性）实测，并与命令层参见边刚发现的问题同构。

## 规范现状
`feature/scripts/build_features.py::build_overview_edges`（v0.12.0）：依赖特性只扫概述「与其他特性的交互」章节、所需License 只扫「可获得性」章节；**无存在性校验**。`build_licenses.py`「对应特性」从段正文提码、同样无校验。两侧 License 口径不一致（特性侧限定章节 vs License 侧段全文）。

实测：

| 缺口 | 数据 |
|---|---|
| 依赖特性覆盖 | UDG 348/396=88%（丢 48 对）、UNC 440/696=**63%**（丢 256 对）；丢因＝概述其他章节与子文档（实现原理/激活/配置指导）的 md 互链与裸特性码 |
| 悬空边 | 现行 788 条中 **35 条指向未建特性**（跨 NF/跨产品码），无校验直接落图 |
| License 双向不对称 | Feature→License 552 vs License→Feature 804（UNC 差 222），口径不一 |
| 特性→命令 | 正文已解析命令引用 25677 处（UDG 7614/UNC 18063）只是引用不是边，"特性用哪些命令"走不了边 |

## 当时怎么处理的
（本次即为修复）用户决策（2026-08-18）：① 依赖特性改全文锚定＋悬空丢弃；② 新增「使用命令」边、子文档各自建；③ License 双侧全文＋校验。

- `build_features.py`：依赖特性/所需License＝概述+全部子文档全文码扫描聚合到概述（特性级关系），候选 ∩ 合法集（同批组码∪已建 / License 已建码），悬空丢弃并计数入 manifest；新增「使用命令」边（`rewrite_doc_refs` 新返回 `cmd_targets`，落在**本文档** ##边，概述/子文档各自建）。
- `_common.py`：新增 `scan_codes`（代码块/TOC/自身排除的逐行锚定扫描）、`build_license_codes`、`group_feature_codes`；`rewrite_doc_refs` 返回 `cmd_targets`。
- `build_licenses.py`：`--feature-dir` 校验「对应特性」（源组码∪已建），悬空丢弃计数。
- `build_all.py`：编排改为 **licenses 先于 features**（特性侧 License 校验需其已建）。
- 回归测试 `feature/scripts/test_build_features_edges.py`（13 用例）。

## 建议的规范补丁
- `feature/SKILL.md` 边表重写（依赖特性/所需License 全文锚定+校验、新增使用命令、License 对应特性校验、构建顺序 licenses→features）
- 根级新增《图谱边定义.md》作为全图层边权威（本次随稿定稿）
- 升版本 0.21.0 + CHANGELOG

## 影响范围
特性层全部资产（Feature UDG 258/UNC 470 文件夹 + License UDG/UNC）需重建；命令层/ConfigObject/Task 层不受影响（Task 层引用的是特性资产本身与命令资产，边类型集合变化不影响其解析）。平台零代码改动（关系名开放），重建后需重索引。

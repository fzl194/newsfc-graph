# CR-20260817-001-Task层去版本

> 状态：✅ 已采纳 / 已落地（v0.19.0，2026-08-17）。

## 场景

用户决策（2026-08-17）：**Task 层剥离版本属性**。理由：atom/compound/feature_task 引用的命令/特性知识本身有版本，但"配置方法/编排"是版本无关的方法论——使用时按目标环境自选命令/特性版本，Task 不应绑死。

平台侧（graph-asset-platform）已于 2026-08-11 先行适配：
- `default_registry.yaml`：Task 三类（Task/AtomTask/CompoundTask/FeatureTask）`scope: task`，`frontmatter_required: [id, type, nf]`（无 version）。
- `classify.py`：task 分支路径 `{layer}/{nf}/`（无 version 目录）。
- 资产磁盘实际布局：**type 名做顶层目录**（`AtomTask/{nf}/`、`CompoundTask/{nf}/`、`FeatureTask/{nf}/`），`fs.py` 上传/移动按 target_dir 驱动。
- DB `resolve_node(id, None)` 落 `[None]` 唯一节点（与 cross 类同处理）。

**规范与资产未同步**：task 层规范全文按"version 只在 YAML+路径"写；资产仍在 `{Type}/{nf}/{ver}/` 三级路径且 YAML 带 `version` 字段；`task/scripts/` 4 个规范脚本按 `{nf}/{ver}` 路径 + `--version` 参数写。

## 建议的规范补丁

1. **Task 层无版本成为层约定**：version 不进 ID（本就不进）、不进 YAML、不进路径。存储 `AtomTask|CompoundTask|FeatureTask/{nf}/`。YAML 由 8 字段变 **7 字段**（id/type/name/name_zh/nf/ref/status；compound 为 command_set）。
2. template 三张 tpl 删 `version:` 行。
3. check.md 字段必填项同步去 version；audit 脚本调用签名改 `--nf {nf}`。
4. agent.md / 批次计划 / 构建提示词 中的版本路径与 `--version` 命令同步更新。
5. 脚本适配（任务4）：4 个规范脚本路径逻辑 `{nf}/{ver}` → `{nf}`，`--version` 对 Command/Feature 输入层保留（这两层仍带版本）、对 Task 层废弃。
6. UNC 计划头部状态刷新（stale"下一批 UNC-A3"→ 实际进度）；UDG 计划头部补 4.1-4.3 完成状态。
7. 顺带记录：`_intermediates/atom-input/`（1350 md）与 5 个旧 zip 已于 2026-08-17 删除（用户批准）；底稿可由 `collect_command_examples.py` 重跑再生。

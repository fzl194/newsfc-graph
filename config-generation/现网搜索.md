## 1. 工具：mml_extract.py

**使用 `scripts/mml_extract.py` 查询现网，禁止逐条 PowerShell Select-String / findstr / grep**（SKILL 铁律6）。

脚本用法：

```bash
# 按命令类型筛选
python scripts/mml_extract.py -f 现网脚本.txt -c "ADD RULE"

# 按命令类型 + 参数筛选（参数名和值均支持正则）
python scripts/mml_extract.py -f 现网脚本.txt -c "ADD URR" -p "RG=133"
python scripts/mml_extract.py -f 现网脚本.txt -c "ADD RULE" -p "RULENAME=l_tk.*"

# ★多命令类型（逗号分隔）——优先使用，一把拉出多类型对象
python scripts/mml_extract.py -f 现网脚本.txt -c "ADD URR,ADD URRGROUP,ADD PCCPOLICYGRP"

# 多参数筛选（AND 关系）——同一命令必须同时满足所有参数条件
python scripts/mml_extract.py -f 现网脚本.txt -c "ADD URR" -p "RG=121" -p "USAGERPTMODE=OFFLINE"

# 统计模式
python scripts/mml_extract.py -f 现网脚本.txt --stats

# 引用追踪——单对象
python scripts/mml_extract.py -f 现网脚本.txt --trace "ffg_tik_ytb"

# ★引用追踪——多对象批量（一次追踪多个对象，避免逐个调用）
python scripts/mml_extract.py -f 现网脚本.txt --trace "ffg_tik_ytb,ffg_rs,cg_tiktok_shaping"

# ★递归追踪——沿 references 方向自动展开多层（避免手动逐层 trace）
python scripts/mml_extract.py -f 现网脚本.txt --trace "cg_tiktok_shaping" --depth 2
# depth=1 = 仅直接引用（等同于旧版 --trace）
# depth=2 = 自动展开到下一层（如 PCCPOLICYGRP→URRGROUP）
# depth=3 = 继续展开（如 URRGROUP→URR）

# JSON 格式输出
python scripts/mml_extract.py -f 现网脚本.txt -c "ADD RULE" --format json
```

> 脚本自动缓存（按文件修改时间失效），后续查询秒返回。跨平台 Python 3.7+，零依赖。

## 2. 强制搜索计划 ★调用前置门控

**未输出搜索计划就发起 mml_extract.py 调用 = 违反契约**（SKILL 铁律12）。

搜索计划分三步，每步必须完整列出后才能执行：

**Step 1 批量广拉**：用多命令类型 + 宽正则一次拉出所有相关对象，而非逐类型逐次查询。

| # | 目标 | 命令类型 (-c) | 参数筛选 (-p) | 说明 |
|---|---|---|---|---|
| 1 | 拉参考业务全链 | {从图谱任务层知识确定} | {从用户需求确定} | 一次拉出所有层对象 |

**Step 2 trace 补链**：对 Step 1 发现的关键引用对象用 `--trace` / `--depth` 补全引用链。

| # | 目标 | trace 对象 | --depth | 说明 |
|---|---|---|---|---|
| 2 | {补全哪条链} | {Step 1 发现的对象名} | {1/2/3} | {展开逻辑} |

**Step 3 定点验证**：仅 Step 1+2 未覆盖的个别对象。

| # | 目标 | 命令类型 (-c) | 参数筛选 (-p) | 说明 |
|---|---|---|---|---|
| 3 | {验证什么} | {命令类型} | {精准参数} | 精准定点查询 |

> **禁止"广撒网"式搜索**——每次调用必须有明确目标参数。
> **禁止计划外搜索**——搜索计划中未列的查询，必须在发起前说明理由并追加到计划中。
> **计划动态调整**：Step 1 结果可能改变 Step 2/3 的内容，允许按结果调整，但调整必须在日志中记录。

## 3. 参数筛选语义关键约束 ★跨命令类型陷阱

`-p` 是**全局 AND**，跨所有命令类型生效。含义：**每条**返回的命令都必须包含该参数且值匹配。

**⚠ 严重陷阱**：不同命令类型的参数集不同！`ADD URR` 有 `RG` 参数，但 `ADD URRGROUP`、`ADD PCCPOLICYGRP`、`ADD RULE` 等命令**没有 `RG` 参数**。如果写：

```bash
# ❌ 错误——ADD URRGROUP/PCCPOLICYGRP 没有 RG 参数，会被全部丢弃，实际只返回 ADD URR
python scripts/mml_extract.py -f 现网脚本.txt -c "ADD URR,ADD URRGROUP,ADD PCCPOLICYGRP" -p "RG=121"
```

**正确做法**：多命令类型 + 参数筛选时，**只对共享该参数的命令类型加 `-p`**，其余类型单独查询或不用 `-p`：

```bash
# ✅ 不共用参数的多类型，不加 -p，全量拉出后过滤
python scripts/mml_extract.py -f 现网脚本.txt -c "ADD URR,ADD URRGROUP,ADD PCCPOLICYGRP"

# ✅ 需要参数筛选时，拆分为只包含该参数的命令类型
python scripts/mml_extract.py -f 现网脚本.txt -c "ADD URR" -p "RG=121"

# ✅ 用 trace/depth 替代多类型+参数筛选
python scripts/mml_extract.py -f 现网脚本.txt --trace "cg_rs_shap_s8m" --depth 3
```

> 制定搜索计划时必须考虑此约束：Step 1 批量广拉的 `-c` 和 `-p` 组合，必须确保每个 `-c` 类型都包含 `-p` 指定的参数名。不确定时，宁可不加 `-p`，或拆成多次查询。

## 4. 现网搜索三条纪律

1. **批量拉取优先**：能用多命令类型 `-c` 一次拉出多类对象，就不要拆成多次逐类型查询。能用宽正则匹配一批，就不要逐个精准查询。**一次调用能拿到的数据绝不分两次**。
2. **trace 结果必须完整消费**：`--trace` / `--depth` 返回的每条 MML 命令行已包含完整参数格式和引用关系。**禁止对 trace/depth 已返回的对象再发起单查**。不够详细用 `--depth` 加深，不要回到逐类型单查。
3. **搜索结果即入 LLD 草稿**：每次现网搜索的结果立即记入现网对象清单（复用判断、命名参考），禁止重复搜索同一对象。Stage 4 直接复用 Stage 2 已收集的现网数据。

**展开纪律**：当现网存在 A 引用 B 的关系时，必须完整提取 A 的所有成员引用，不得只取 A 名字就跳过。使用 `--trace` + `--depth` 追踪。

## 5. 搜索日志 ★每次调用后必须输出

每次执行 mml_extract.py 后，必须输出搜索日志（SKILL 铁律12）：

```
[现网] #{N} {步骤} {命令简述} | 返回:{N条} | 新增:{对象} | 累计已获取:{...}
```

**累计已获取对象清单**：每条日志追加到累计清单。发起新查询前，**必须先检查目标对象是否已在累计清单中**。已在 = 重复搜索 = 禁止发起。

示例：
```
[现网] #1 S1-1 -c "ADD RULE,ADD PCCPOLICYGRP" -p "RULENAME=l_tk.*" | 返回:12条RULE+1条PCC | 新增:l_tk_nu_1265,cg_tiktok_shaping | 累计:{l_tk_nu_1265,cg_tiktok_shaping}
[现网] #2 S2-1 --trace "cg_tiktok_shaping" --depth 3 | 返回:完整链PCC→URRGROUP→URR | 新增:cp_tiktok_shap_11,cbb_tiktok_shap_offline,cbb_tiktok_shap_online | 累计:{l_tk_nu_1265,cg_tiktok_shaping,cp_tiktok_shap_11,...}
```

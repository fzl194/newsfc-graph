# 图谱接口（MCP）

> 本文件是 `config-generation` 当前启用的图谱访问依赖。所有图谱查询必须通过已连接的
> Graph MCP 服务完成，**禁止 curl、禁止 HTTP POST、禁止在 MCP 不可用时自行降级到
> REST**。若工具不可见或鉴权失败，停止当前阶段并报告缺少图谱依赖。
>
> 2026-09-08 三工具重构：公开工具收敛为 `get_domains` / `search_graph` / `get_md`。
> 旧工具（search_objects/search_md/get_object）已 hidden——若客户端缓存了旧 schema
> 仍能调到，**不要使用**（deprecated，随时可能 disabled）。

---

## 0. 调用上下文（每次工具调用必传）

Graph MCP 连接的 `X-API-Key` 由平台配置负责，不作为工具参数传入。调用任意图谱工具时，
都必须同时传递：

| MCP 参数 | 值来源 | 打点字段 | 规则 |
|---|---|---|---|
| `AGENT_USERNAME` | 环境变量 `_AGENT_USERNAME` | `operator` | 工号；去首尾空白，非空，最长 64 字符 |
| `AGENT_SESSION_ID` | 环境变量 `_AGENT_SESSION_ID` | `session_id` | 会话 ID；去首尾空白，非空，最长 128 字符 |

两个参数只用于调用归因和统计，不参与鉴权。不得臆造、复用其他用户的值，也不得省略。
传未知参数会被拒绝（INVALID_ARGUMENT）——工具 schema 即契约。

---

## 1. MCP 工具总览

| 工具 | 用途 | 配置生成中的位置 |
|---|---|---|
| `get_domains` | 返回全部业务域完整 md + references | Stage 1 固定入口 |
| `search_graph` | 多关键词统一搜索（元数据 + 正文） | ID 不确定时定位候选 |
| `get_md` | 按 ID 批量返回完整 md + 元数据 + references | 全程下钻主力；**权威原文唯一来源** |

配置生成以 `get_domains → get_md` 沿 `[[ID]]` 下钻为主。`search_graph` 只负责找候选 ID；
选中候选后必须用 `get_md` 读取完整原文——**snippet 不是权威依据**。

---

## 2. 业务域入口：`get_domains`

调用参数示意：

```json
{
  "AGENT_USERNAME": "00234567",
  "AGENT_SESSION_ID": "session-20260908-001"
}
```

返回：

```text
{"domains": [{"id": "...", "type": "BusinessDomain", "name": "...", "version": null,
              "md": "...", "references": ["NetworkScenario@charging", ...]}, ...]}
```

每个 `md` 都是完整原文（frontmatter + 正文 + `## 边`）；`references` 已从全文提取
`[[ID]]` 引用（去重保序），可直接作为下钻候选。Stage 1 先通读业务域 md，再按
`references`（或自行正则扫描）取 `[[NetworkScenario@*]]` 引用。

---

## 3. 批量取原文：`get_md`

调用参数示意：

```json
{
  "ids": [
    "NetworkScenario@charging",
    "ConfigurationSolution@charging-online"
  ],
  "AGENT_USERNAME": "00234567",
  "AGENT_SESSION_ID": "session-20260908-001"
}
```

参数：

- `ids`：必填，1～100 个逻辑 ID；重复 ID 自动去重保序（key = trim 后规范 ID）。
- `version`：可选的全局版本。不传时，每个 ID 各取最新现存版本。
- `AGENT_USERNAME`、`AGENT_SESSION_ID`：每次必传，规则见 §0。

返回 `{id: MdSuccess | MdFailure}`：

- 成功项：`{ok:true, id, type, name, nf, domain, scenario, version, versions[],
  md, references}`——`md` 为完整原文；`references` 为全文 `[[ID]]` 引用去重保序。
- 失败项：`{ok:false, id, error_code: OBJECT_NOT_FOUND|VERSION_NOT_FOUND, error,
  requested_version, available_versions}`——只在该 ID 条目计错，其余 ID 仍正常返回；
  **不重试整批**。

单次总响应上限为 2 MB（按业务 map 紧凑 JSON UTF-8 字节计量）；实际调用建议每批
5～20 个 ID，超限（RESULT_TOO_LARGE）后按相关性拆批重试。

**MMLCommand 参数字段范围、类型、枚举、必填与约束以本工具返回的 CommandParameter
段为准。**

## 4. 统一搜索：`search_graph`

不知道对象 ID 时的定位入口。同时搜索元数据（id/name/name_zh）与 md 正文。

```json
{
  "terms": ["计费欺诈", "免费流量", "免费RG"],
  "match": "any",
  "AGENT_USERNAME": "00234567",
  "AGENT_SESSION_ID": "session-20260908-001"
}
```

参数：

- `terms`：必填，1～10 个关键词（每项 1～80 字符）。**每项是一个字面关键词或短语**：
  `"ADD URR"` 是含空格的完整短语；`["计费欺诈","免费RG"]` 是两个独立词。禁止把
  全部同义词拼成一个带空格的长字符串——空格意味着"连续短语"，多关键词请拆成
  数组多项。短词（<3 字符，如 `N2`、`RG`）最多 3 个。
- `match`：`any`（默认，任一命中即召回——**召回优先，先用 any**）/ `all`（全部
  命中，位置可分散——仅在 any 结果过多需要精确收窄时用）。
- 过滤：`layer`（命令层/特性层/任务层/业务层）/ `type` / `nf` / `version` /
  `domain` / `scenario`；不确定的过滤**不要传**，先看返回 facets 再收窄。
  非法值返回 `INVALID_FILTER` + `available_values`（不是 0 结果）；`layer`+`type`
  同传按交集，冲突报错。
- `page`(1) / `size`(20，≤50)。

返回 `{terms, match, applied_filters, total, page, size, has_more, next_page,
hits[], facets, diagnostics, suggestions}`：

- `hits[]`：`{id, type, layer, name, ..., matched_terms[], matched_in[],
  snippets[{term,text}](≤3), rank_reasons[]}`。排序：命中词数 → 元数据等级
  （id 全等 > 名称全等 > 前缀 > 包含）→ 正文相关度 → (type, id)。
- `facets`：当前结果构成（layers/types/nfs/versions 计数）——用于决定下一步过滤。
- `diagnostics.term_counts`：每词命中数；零结果时 `recovery_codes` 给出恢复建议
  （USE_MATCH_ANY / REMOVE_OR_REPHRASE_TERM / RELAX_FILTERS）。
- 翻页：`has_more`/`next_page`；`total` 是精确总数。

错误：`SEARCH_TOO_BROAD`（命中量超预算）→ 增加 nf/type/layer 过滤后重试。

## 5. 下钻纪律：读 md → 提引用 → 循环

1. Stage 1 调用 `get_domains` 获取全部业务域 md。
2. 其他层调用 `get_md` 批量获取完整原文。
3. 优先用返回的 `references` 字段（等价于对每个 md 全文执行正则
   `\[\[([^\]]+)\]\]`，正文和 `## 边` 都已覆盖）。
4. 按当前配置目标判断引用相关性：相关的进入下一批，无关的记录理由后跳过。
5. 用“候选 ID − 已取 ID”得到下一批，继续 `get_md`，直到当前阶段所需知识齐备。

典型链路：

```text
get_domains                         → 全部业务域 md（references），锁定域
读域 md → [[NetworkScenario@*]]     → get_md 读场景，按决策点选择方案
读方案 md                           → get_md 读相关 FeatureTask/CompoundTask/AtomTask
读 task md                          → get_md 按需读 Feature/MMLCommand/ConfigObject/License
不知道 ID                           → search_graph（terms 数组 + match=any）定位候选
```

方案 md 的正文和 `## 边` 会共同声明 task 编排；只看任何单一段落都可能漏引用。

## 6. 结果处理与失败规则

- 直接阅读 MCP 工具返回内容；禁止为了转存或转换而调用 shell、创建中间 JSON 文件。
- 工具错误统一为 `content[0].text` 里的 `{"error":{code,message,retryable,details}}`：
  - `get_md` 单个 ID `ok:false`：看 `available_versions` 按需改版本或跳过；不能把
    该条失败误判为整批失败，也不重试整批。
  - `INVALID_ARGUMENT`：修正字段（含工号/会话缺失、超长），不要原样重试。
  - `INVALID_FILTER` / `INVALID_FILTER_COMBINATION`：从 `details.available_values`
    选择或移除过滤。
  - `RESULT_TOO_LARGE`：拆小批次；`SEARCH_TOO_BROAD`：加过滤；`INDEX_REBUILDING`：
    稍等重试（retryable=true）。
  - `INTERNAL_ERROR`：最多重试一次后报告。
- 工具不可见、连接失败、401 或 403 时立即停止并报告；禁止绕过 MCP 改调 REST。

---

## 7. ID 格式

- 业务层：`{Type}@{slug}`，如 `NetworkScenario@charging`。
- NF 类：`{nf}@{Type}@{name}`，如 `UDG@AtomTask@SET UPDEFAULTQUOTA`。
- `@` 与空格在 MCP 字符串参数中直接传递，无需 URL 编码。

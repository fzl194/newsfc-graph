# 图谱接口（MCP）

> 本文件是 `config-generation` 当前启用的图谱访问依赖。所有图谱查询必须通过已连接的
> Graph MCP 服务完成，**禁止 curl、禁止 HTTP POST、禁止在 MCP 不可用时自行降级到
> REST**。若工具不可见或鉴权失败，停止当前阶段并报告缺少图谱依赖。

---

## 0. 调用上下文（每次工具调用必传）

Graph MCP 连接的 `X-API-Key` 由平台配置负责，不作为工具参数传入。调用任意图谱工具时，
都必须同时传递：

| MCP 参数 | 值来源 | 打点字段 | 规则 |
|---|---|---|---|
| `AGENT_USERNAME` | 环境变量 `_AGENT_USERNAME` | `operator` | 工号；去首尾空白，非空，最长 64 字符 |
| `AGENT_SESSION_ID` | 环境变量 `_AGENT_SESSION_ID` | `session_id` | 会话 ID；去首尾空白，非空，最长 128 字符 |

两个参数只用于调用归因和统计，不参与鉴权。不得臆造、复用其他用户的值，也不得省略。

---

## 1. MCP 工具总览

| 工具 | 用途 | 配置生成中的位置 |
|---|---|---|
| `get_domains` | 返回全部业务域完整 md | Stage 1 固定入口 |
| `get_md` | 按 ID 批量返回完整 md | 全程下钻主力 |
| `search_objects` | 按名称、层、类型、网元等搜索对象元数据 | ID 不确定时定位候选 |
| `search_md` | 按业务关键词搜索正文并返回片段 | 仅凭名称找不到时召回候选 |
| `get_object` | 返回单对象结构化详情与 curated 出边 | 需要结构化字段时辅助查看 |

配置生成仍以 `get_domains → get_md` 沿 `[[ID]]` 下钻为主。搜索工具只负责找候选 ID；
选中候选后必须用 `get_md` 读取完整原文。

---

## 2. 业务域入口：`get_domains`

调用参数示意：

```json
{
  "AGENT_USERNAME": "从 _AGENT_USERNAME 读取",
  "AGENT_SESSION_ID": "从 _AGENT_SESSION_ID 读取"
}
```

返回：

```text
{"domains": [{"id": "...", "name": "...", "md": "..."}, ...]}
```

每个 `md` 都是完整原文（frontmatter + 正文 + `## 边`）。Stage 1 先通读业务域 md，
再从全文提取 `[[NetworkScenario@*]]` 引用。

---

## 3. 批量取原文：`get_md`

调用参数示意：

```json
{
  "ids": [
    "NetworkScenario@charging",
    "ConfigurationSolution@charging-online"
  ],
  "AGENT_USERNAME": "从 _AGENT_USERNAME 读取",
  "AGENT_SESSION_ID": "从 _AGENT_SESSION_ID 读取"
}
```

参数：

- `ids`：必填，1～100 个逻辑 ID；重复 ID 自动去重保序。
- `version`：可选的全局版本。不传时，每个 ID 各取最新现存版本。
- `AGENT_USERNAME`、`AGENT_SESSION_ID`：每次必传，规则见 §0。

返回 `{id: {version, md} | {error, available_versions}}`。某个 ID 不存在或指定版本缺失时，
只在该 ID 条目返回错误，其余 ID 仍正常返回。单次总响应上限为 2 MB；实际调用建议每批
不超过 50 个 ID，超限后按相关性拆批重试。

---

## 4. 定位辅助工具

### `search_objects`

按 `q`、`layer`、`type`、`nf`、`version`、`domain`、`scenario` 等条件查元数据。
它不搜索正文，适合已经知道对象名、命令名、层或网元时定位 ID。`type` 与 `layer`
同时传入时以 `type` 为准；`page` 默认 1，`size` 默认 50。返回
`{total, rows:[{id,type,layer,nf,domain,scenario,name,versions[]}]}`。若 `total` 大于
当前已返回数量，必须继续翻页，不能把第一页当作完整候选集。

### `search_md`

按 `q` 搜索正文，可用 `layer`、`type`、`nf`、`version` 等条件收窄。返回的是相关片段，
不是完整 md；`type` 与 `layer` 同时传入时以 `type` 为准。`limit` 默认 20，`offset`
默认 0，返回 `{total, hits:[{id,type,name,version,score,snippet}]}`。若 `total` 大于当前
已返回数量，必须按 `offset` 继续取；选中候选后必须调用 `get_md` 读取完整原文。

### `get_object`

传 `id` 和可选 `version`，返回 frontmatter、正文、版本与 `out_edges` 等结构化字段。
精确返回键包括 `{id,type,layer,scope,nf,version,domain,scenario,frontmatter,body_md,
source_path,versions[],out_edges[]}`。`out_edges` 只包含 curated 边，不能代替对完整
md 的 `[[ID]]` 扫描。

以上三个工具也必须传 §0 的两个调用上下文参数。

---

## 5. 下钻纪律：读 md → 提引用 → 循环

1. Stage 1 调用 `get_domains` 获取全部业务域 md。
2. 其他层调用 `get_md` 批量获取完整原文。
3. 对每个 md 全文执行正则 `\[\[([^\]]+)\]\]`，正文和 `## 边` 都必须扫描。
4. 按当前配置目标判断引用相关性：相关的进入下一批，无关的记录理由后跳过。
5. 用“候选 ID − 已取 ID”得到下一批，继续 `get_md`，直到当前阶段所需知识齐备。

典型链路：

```text
get_domains                         → 全部业务域 md，锁定域
读域 md → [[NetworkScenario@*]]     → get_md 读场景，按决策点选择方案
读方案 md                           → get_md 读相关 FeatureTask/CompoundTask/AtomTask
读 task md                          → get_md 按需读 Feature/MMLCommand/ConfigObject/License
```

方案 md 的正文和 `## 边` 会共同声明 task 编排；只看 `out_edges` 或 `## 边` 都可能漏引用。

---

## 6. 结果处理与失败规则

- 直接阅读 MCP 工具返回内容；禁止为了转存或转换而调用 shell、创建中间 JSON 文件。
- `get_md` 的单个 ID 返回 `error` 时，先看 `available_versions`，按需改版本或跳过；不能把
  该条失败误判为整批失败。
- 工号/会话缺失、为空或超长会触发 MCP 参数校验错误；补齐正确环境变量后重试。
- 工具不可见、连接失败、401 或 403 时立即停止并报告；禁止绕过 MCP 改调 REST。

---

## 7. ID 格式

- 业务层：`{Type}@{slug}`，如 `NetworkScenario@charging`。
- NF 类：`{nf}@{Type}@{name}`，如 `UDG@AtomTask@SET UPDEFAULTQUOTA`。
- `@` 与空格在 MCP 字符串参数中直接传递，无需 URL 编码。
